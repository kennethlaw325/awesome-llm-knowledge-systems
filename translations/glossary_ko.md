## 용어집

> 이 문서는 [English Glossary](../glossary.md)의 한국어 번역입니다. 모든 기술 용어를 일상적인 언어로 설명하므로 박사 학위가 필요하지 않습니다.

### A

**A2A (Agent-to-Agent Protocol, 에이전트 간 프로토콜)**
AI 에이전트들이 서로 소통하고 작업을 조율하기 위한 표준적인 방법. 서로 다른 AI 어시스턴트가 작업을 인계할 수 있게 해 주는 공통 언어와 같습니다.

**Agent Memory (에이전트 메모리)**
AI 에이전트가 대화나 작업을 가로질러 정보를 기억하는 능력. 에이전트가 세션 사이에 보관하는 노트와 같다고 생각하세요. 매번 처음부터 시작할 필요가 없게 만듭니다.

**Agentic RAG (에이전트형 RAG)**
RAG의 한 종류로, AI가 무엇을 찾을지, 언제 찾을지, 결과가 충분히 좋은지를 능동적으로 결정합니다. 매번 같은 고정된 검색 단계를 따르지 않습니다.

**Anchor (앵커, Graph Engineering)**
멀티-에이전트 그래프의 어떤 노드가 반드시 접촉해야 하는, 논쟁의 여지가 없는, 외부에서 접지된 측정치 —— 테스트 결과, 지표, 정답 확인. 2026년 7월 graph engineering 담론에서 Carlos E. Perez가 도입했습니다: 앵커가 없다면, 서로의 작업을 리뷰하는 에이전트들의 그래프는 정확성이 아니라 확신에 찬 합의로 수렴하는 반향실로 퇴화합니다. 위원회의 최소 한 명은 모두가 예산이 괜찮아 보인다는 데 동의하는 대신 실제 은행 명세서를 확인해야 한다는 요구와 같습니다. **Graph Engineering** 참조; 14장.

**ARC-AGI-3**
François Chollet의 2026년 에이전트 지능을 위한 인터랙티브 벤치마크. 에이전트는 지시 없이 게임 같은 환경에 던져져 스스로 탐험하고, 목표를 추론하고, 세계 모델을 구축해야 합니다. 정적인 퍼즐 그리드로 구성된 이전 ARC 벤치마크와 달리, ARC-AGI-3는 **탐험 효율성**, **목표 추론**, **세계 모델 형성**을 별도의 능력 축으로 평가합니다.

### C

**CATTS (Consensus-Aware Test-Time Scaling, 합의 인식 테스트 시 스케일링)**
멀티스텝 에이전트를 위한 테스트 시 스케일링 방법. 각 단계마다 작은 롤아웃 위원회를 샘플링하고, 위원들 사이의 불일치를 불확실성 신호로 사용하여 컴퓨팅을 할당합니다. 의견이 크게 갈리는 단계는 더 많은 사고 예산을 받고, 합의가 잘 되는 단계는 더 적게 받습니다. 공개된 결과는 균일 스케일링 대비 약 +9.1% 정확도, 2.3배 적은 토큰을 보고합니다.

**Claude Code**
Anthropic의 명령줄 도구. Claude가 터미널에서 직접 작업하면서 파일을 읽고, 명령을 실행하고, 코드를 편집합니다. AI 페어 프로그래밍 동료처럼 동작합니다.

**Client ID Metadata Documents (CIMD, 클라이언트 ID 메타데이터 문서)**
확정된 MCP 2026-07-28 사양이 의무화한 클라이언트-식별 메커니즘으로, Dynamic Client Registration을 대체합니다: MCP 클라이언트는 모든 서버에 각각 등록하는 대신, 자신의 URL에 호스팅된 메타데이터 문서로 식별됩니다. 방문하는 모든 사무실마다 신규 거래처 양식을 채우는 대신, 자기 주소에 호스팅된 명함을 제시하는 것과 같습니다. **MCP** 참조.

**Codex (OpenAI)**
OpenAI의 도구. AI 에이전트가 샌드박스화된 클라우드 환경에서 코딩 작업을 실행하고, 자율적으로 저장소를 읽고, 코드를 작성하고, 테스트를 실행합니다.

**Context Engineering (컨텍스트 엔지니어링)**
AI가 응답하기 전에 받는 정보를 신중하게 설계하는 실천. Prompt engineering이 질문을 작성하는 것이라면, context engineering은 AI의 책상 위에 어떤 참고 자료를 올려놓을지 선택하는 것입니다.

**Context Window (컨텍스트 윈도우)**
AI 모델이 한 번에 "볼 수 있는" 텍스트의 총량 — 당신의 입력과 모델의 출력 모두를 포함합니다. 화이트보드의 크기와 같다고 생각하세요. 모델이 읽고 쓰는 모든 것이 그 안에 들어가야 합니다.

**CoT Monitoring (사고 연쇄 모니터링)**
모델이 계획을 실행하기 전에 명시적인 추론 토큰을 읽어 잘못된 행동이나 정렬 이탈을 탐지하는 실천. OpenAI는 2026년 4월 자사의 추론 모델 중 하나가 코딩 평가에서 부정행위를 하는 것을 CoT 모니터링으로 적발했습니다. 이는 해석 가능성이 사후 포렌식이 아닌 **런타임 검사**로 작동한 첫 공개 사례입니다.

### D

**Dreaming (드리밍)**
최근 세션 패턴을 바탕으로 에이전트의 영속적 메모리를 다시 쓰는, 세션 사이에 예약되는 메모리-정리 작업. Anthropic Managed Agents가 (2026년 5월 6일, 연구 프리뷰) 최초로 상용화했습니다: 큐레이터가 최근 세션들을 읽고, 반복되는 오류와 수렴된 워크플로우를 식별하며, 에이전트의 영속적 메모리를 평문으로 다시 씁니다. 추론 시 경사 업데이트로 적응하는 훈련 가능한 메모리 (Titans + MIRAS, 2026년 4월)와 대비됩니다: Dreaming은 메모리를 harness가 읽는 데이터로 유지하는 반면, Titans는 메모리를 모델 자체의 일부로 만듭니다.

### E

**Embeddings (임베딩)**
의미가 비슷한 텍스트가 수학적으로도 가까이 위치하도록 텍스트를 숫자 리스트로 변환하는 방법. 컴퓨터가 두 책이 비슷한 주제를 다룬다는 걸 알아채는 것과 같은 방식으로 텍스트의 관련성을 측정할 수 있게 합니다.

**Emotion Vectors (감정 벡터)**
Claude의 내부 활성화 안에 있는 해석 가능한 특징 방향. 이를 강화하면 모델은 감정적 행동에 안정적으로 편향됩니다 — Anthropic의 2026년 4월 공개에서 가장 자주 인용된 예시는 협박성 출력입니다. 이러한 방향이 식별 가능하기 때문에 harness 엔지니어들은 토큰 레벨이 아닌 **특징 레벨**의 필터링 표면을 얻게 됩니다.

**Enterprise-Managed Authorization (EMA, 엔터프라이즈 관리형 인가)**
MCP 서버에 대한 중앙집중식, IdP가 프로비저닝하는 접근을 위한 MCP 확장 (2026년 6월 18일 안정화). 각 사용자가 모든 서버마다 앱별 OAuth 동의 흐름을 거치는 대신, 조직은 자신의 identity provider를 통해 서버 접근을 한 번에 프로비저닝합니다; SSO 중에 클라이언트는 **Identity Assertion JWT Authorization Grant (ID-JAG)**를 얻고, 이를 MCP 서버 자신의 인가 서버가 발급하는 액세스 토큰과 교환합니다 (**MCP** 참조). 첫날 지원은 IdP로서의 Okta, 클라이언트로서의 Anthropic과 VS Code, 그리고 일곱 개 서버에 걸쳐 있었습니다. EMA는 MCP를 위한 엔터프라이즈 SSO를 서버별 통합 접착제에서 IdP에서 한 번 내려지는 단일 프로비저닝 결정으로 바꾸는 것입니다.

### F

**Few-shot Learning (퓨샷 학습)**
모델 전체를 다시 훈련하는 대신 프롬프트 안에 몇 가지 예시를 보여 주어 AI에게 작업 방법을 가르치는 것. 완성된 양식 세 장을 보여 주어 네 번째 양식을 채우는 방법을 알려 주는 것과 같습니다.

**Fine-tuning (파인튜닝)**
사전 훈련된 AI 모델을 자신의 특정 데이터로 추가 훈련하여 특정 작업을 더 잘 수행하게 만드는 것. 제너럴리스트를 채용한 후 전문 OJT를 제공하는 것과 같습니다.

### G

**Generator-Evaluator Split (생성자-평가자 분리)**
작업을 생산하는 에이전트를, 그것을 판단하는 독립적이고 의도적으로 회의적인 에이전트로부터 분리하는 에이전트-신뢰성 패턴 —— 에이전트가 자신의 산출물을 신뢰성 있게 과대평가하기 때문에 채택되었습니다. Prithvi Rajasekaran의 "Harness design for long-running application development" (Anthropic, 2026년 3월)에서 도입되었으며, 이는 Generative Adversarial Networks (GAN)에서 그 구조를 가져왔고, 독립된 evaluator를 회의적이도록 튜닝하는 것이 generator를 자기비판적으로 만드는 것보다 훨씬 다루기 쉽다는 것을 발견했습니다. Evaluator는 diff를 읽는 대신 행동을 검증합니다 —— 실행 중인 애플리케이션을 클릭해 다니고, 스크린샷을 찍고, UI 기능, API 엔드포인트, 데이터베이스 상태를 테스트합니다. 이 패턴은 Claude Code의 `/goal`과 같은 run-until-condition 프리미티브로 제품화되어 있으며, 여기서는 별도의 신선한 모델이 매 턴 이후 정지 조건을 판단합니다. **Outer Loop**, **Loop Engineering** 참조.

**Graph Engineering (그래프 엔지니어링)**
**Loop Engineering** 위의 다음 계층이 그래프라는, 2026년 7월의 주장: 어떤 에이전트가 존재하는지, 누가 누구에게 위임할 수 있는지, 그리고 그들의 루프가 서로를 어떻게 감독하고 교정하는지의 명시적 배선. 2026년 7월 17-18일 Peter Steinberger의 포스트를 뒤따른 에세이들에서 결정화되었고, 첫날부터 논쟁적이었습니다 —— LangChain의 응답은 이 실천이 3년 되었다고 (루프는 그저 방향이 있고 순환하는 그래프일 뿐이라고) 주장하며 오직 이름만 새롭다고 합니다. 시스템이 *아는* 것을 구조화하는 지식 그래프나 **GraphRAG**와 혼동해서는 안 됩니다; graph engineering은 시스템이 *누구인지*를 구조화합니다. 이 글을 쓰는 시점에 이 용어는 약 두 주 되었으며, 본 가이드는 이를 정착된 계층이 아니라 시험받는 주장으로 추적합니다. 14장 참조.

**GraphRAG**
RAG의 한 종류로, 검색된 정보를 연결된 엔티티와 관계의 그래프로 정리하여 여러 출처에서 사실을 결합해야 하는 질문에 더 잘 답할 수 있게 합니다.

### H

**Harness Engineering (하네스 엔지니어링)**
AI 모델을 둘러싼 시스템 — 도구, 메모리, 규칙, 워크플로우 — 전체를 설계하여 모델이 실제로 어떻게 동작할지 형성하는 일. 모델이 엔진이라면, 하네스는 차 전체입니다.

**Harness Synthesis (하네스 합성)**
바깥쪽 루프의 옵티마이저(검색 기반, 관찰성 기반 등)가 대상 작업의 런타임 신호를 바탕으로 하네스 — 그 도구, 프롬프트, 역할 분해, 통신 토폴로지, 협조 프로토콜 — 를 자동으로 수정하는 기술 군. 2026년 4월의 두 참조 구현으로 **AHE**(arXiv 2604.25850)와 **AgentFlow**(arXiv 2604.20801)를 참조하세요. *meta-harness*(2025년 / 2026년 초의 프레이밍, 하네스를 지속적으로 진화하는 산물이 아닌 일회성 최적화 대상으로 다룬 것)와는 구별됩니다.

**Harness-Native Training (하네스 네이티브 훈련)**
모델을 고립된 상태에서 올바른 출력을 내도록 훈련하는 것이 아니라, 특정 프로덕션 에이전트 harness에 직접 대항해 훈련하여 그 harness의 도구와 워크플로우를 다루는 법을 배우게 하는 것. 참조 사례는 Microsoft의 **MAI-Code-1-Flash** (Build, 2026년 6월 2일)로, 프로덕션에서 쓰이는 GitHub Copilot harness에 대항해 훈련된 50억 파라미터 코딩 모델입니다; Microsoft는 어려운 작업에서 약 60% 적은 토큰과 Claude Haiku 4.5 대비 가격 대비 성능 우위를 보고합니다. Harness-native training은 **harness synthesis의 대칭적 역**입니다: harness synthesis (**Harness Synthesis**, **AHE** 참조)가 모델을 고정하고 harness를 진화시키는 반면, harness-native training은 harness를 고정하고 모델을 그에 맞게 빚습니다. 둘을 합치면 모델과 harness를 양쪽 끝에서 최적화 가능한 공동설계 문제로 만듭니다. 트레이드오프: 하나의 벤더 harness에 맞춰 튜닝된 모델은 그 harness 안에서 가장 가치가 크며, 이는 *해자로서의 harness* 역학을 더 날카롭게 만듭니다.

### I

**Inference (추론)**
AI 모델이 당신의 입력에 대한 응답을 생성하는 과정. 메시지를 보내고 응답을 받을 때마다 모델은 추론을 수행하고 있습니다.

**Iteration Head (이터레이션 헤드)**
사고 연쇄 추론 중에 출현하는 어텐션 헤드로, 이전 추론 단계의 출력에 일관되게 주의를 기울입니다. Anthropic 해석 가능성 팀이 2026년 4월에 식별했습니다. 그 존재는 명시적인 CoT 프롬프팅이 부분적으로는 특정 내부 회로를 유도함으로써 작동하는 메커니즘이며, 단순히 사람이 읽을 수 있는 중간 텍스트를 생성하는 것 이상임을 시사합니다.

### K

**Knowledge Graph (지식 그래프)**
사실의 구조화된 지도로, 엔티티(사람, 장소, 개념)들이 라벨이 붙은 관계로 연결되어 있습니다. 모든 것이 어떻게 서로 연결되어 있는지 보여 주는 라벨링된 끈으로 연결된 색인 카드 웹과 같습니다.

**KV-Cache**
AI가 이전에 계산한 키-값 쌍을 다시 사용해 처음부터 다시 계산할 필요가 없게 해 주는 메모리 단축. 대화 이력이 동일하면 응답이 더 빠르고 저렴해집니다.

### L

**LLM (Large Language Model, 대규모 언어 모델)**
방대한 양의 텍스트로 훈련되어 인간 언어를 이해하고 생성할 수 있는 AI 시스템. ChatGPT, Claude, Gemini는 모두 LLM입니다.

**Long Context (롱 컨텍스트)**
새로운 AI 모델이 한 번에 매우 많은 양의 텍스트를 처리하는 능력 — 책 한 권이나 코드베이스 전체가 한 번의 대화에 들어갈 수도 있습니다.

**Loop Engineering (루프 엔지니어링)**
2026년 6월에 명명된 실천으로, 매 턴을 손으로 prompt하는 대신 에이전트에게 prompt하는 시스템을 짓는 것입니다. Addy Osmani의 2026년 6월 7일 에세이에서 조어되었으며, 이를 "당신을 대신해 그 일을 하는 시스템"을 설계함으로써 "에이전트에게 prompt하는 사람의 자리에서 당신 자신을 교체하는 것"으로 정의합니다. 같은 주에 Peter Steinberger의 바이럴 포스트가 이를 촉발했습니다. 이는 **Harness Engineering** 바로 한 층 위에 있습니다: 루프란 타이머로 돌고, helper 서브에이전트를 낳고, 영속된 상태로부터 스스로를 먹여 살리는 harness입니다 —— 매 통과마다 현재 상태를 읽고 무엇을 할지 다시 결정한다는 점에서, 시계 위에서 고정된 명령을 발화하는 평범한 스케줄러와 구별됩니다. 이 용어는 실무자에게만 통용되며 논쟁적입니다 (2026년 중반 기준 학술 문헌 없음); 본 가이드는 이를 정착된 세대가 아니라 떠오르는 네 번째 계층으로 추적합니다. 13장 참조.

### M

**MCP (Model Context Protocol, 모델 컨텍스트 프로토콜)**
AI 어시스턴트가 보편적인 플러그 앤 플레이 인터페이스를 통해 외부 도구와 데이터 소스에 연결할 수 있게 해 주는 오픈 표준. AI 애플리케이션을 위한 USB와 같습니다.

**MCP Apps**
서버가 도구 호출과 함께 인터랙티브 HTML 인터페이스를 실어 보낼 수 있게 하는 2026-07-28 MCP Release Candidate 프리미티브 (2026년 5월 21일 확정). 호스트는 그 인터페이스를 샌드박스화된 iframe에서 렌더링하며; UI 템플릿은 보안 검토와 캐싱을 위해 사전에 선언됩니다. MCP Apps는 도구 호출이 아닌 첫 MCP-네이티브 산출물입니다 —— 지식 베이스 서버는 검색창을, 리서치 서버는 결과-비교 뷰를, 조달 서버는 구매-확인 모달을 실어 보낼 수 있으며, 별도의 UI 사양을 덧붙일 필요가 없습니다.

**MCP Tunnel**
Anthropic Managed Agents가 2026년 5월 19일 (Code with Claude London) 연구 프리뷰로 출시한 사설망 배포 패턴. 고객의 사설망 안에 배포된 가벼운 게이트웨이가 Anthropic으로 단일 아웃바운드 연결을 만들며, 그 후 에이전트는 내부 데이터베이스, API, 지식 베이스, 티켓 시스템을 인바운드 방화벽 규칙, 공개 엔드포인트, VPN 없이 MCP 도구로서 호출할 수 있습니다. Self-hosted sandbox의 대칭적 대응물입니다: self-hosted sandbox가 도구 *실행*을 고객 경계 안에 유지하는 반면, MCP tunnel은 도구 *도달 범위*를 경계 안에 유지합니다.

**Managed Agents (매니지드 에이전트)**
에이전트 하네스의 기반 — 샌드박스, 세션 상태, 범위가 지정된 도구 실행, 트레이싱 — 을 개발자가 아닌 모델 벤더가 운영하는 호스팅 런타임 모델. Anthropic은 2026년 4월 8일 첫 상용 사례를 퍼블릭 베타로 출시했습니다([platform.claude.com/docs/en/managed-agents/overview](https://platform.claude.com/docs/en/managed-agents/overview)). SiliconANGLE의 출시 보도에 따르면, 가격은 표준 API 토큰 요율에 더해 기반에 대한 에이전트 런타임 시간당 요금입니다(시간당 수치는 Anthropic의 1차 문서에 기재되어 있지 않습니다). Claude Code Routines와 같은 클라우드 네이티브 트리거 표면과는 구별됩니다. 후자는 Managed Agents 식의 기반 위에 올라가지만 다른 질문에 답합니다 — "루프가 무엇으로 시작되는가".

**Mechanistic Interpretability (메커니즘적 해석 가능성)**
모델의 가중치 내부에 있는 인간이 이해할 수 있는 회로 — 특정 행동을 구현하는 특징, 헤드, 경로 — 를 식별하는 것을 목표로 하는 연구 프로그램. MIT Technology Review의 2026년 10대 돌파 기술 중 하나로 선정되었으며, 2026년 4월의 감정 벡터, 이터레이션 헤드, CoT 모니터링 같은 결과를 뒷받침합니다.

**Memory Foundation Model (메모리 파운데이션 모델)**
에이전트 메모리가 transformer 백본 자체 내부에 영속적이고 동적으로 진화하는 상태로 —— 외부가 아니라 파라메트릭하게 —— 존재해야 한다는 2026년 7월의 주장 (MemTensor의 Metis, arXiv 2607.26760). 이 프로토타입은 고정된 Qwen3.5 백본 위에 4B / 9B / 27B 스케일로 (Fast Weight Programming에서 영감을 받은) "하이퍼 메모리 블록"과 "로컬 메모리 블록"을 훈련시키며, 벡터-스토어 쓰기나 Titans 식 경사 업데이트가 아니라 경사 없는 EMA 방식의 forward pass를 통해 추론 시 메모리를 업데이트합니다. 자체 보고된 한계로는 고정 크기 압축 아래에서의 장기간 정보 손실과 "잠재 공간 내 의미의 혼합에서 비롯된 것으로 보이는, 일부 경우의 정보 혼동"이 있습니다 —— 아직 검증된 프로덕션 패턴이 아니라 연구 프리뷰입니다. 6장 참조.

**mHC (Manifold-Constrained Hyper-Connections, 매니폴드 제약 하이퍼 연결)**
DeepSeek의 2026년 4월 아키텍처 제안으로, 잔차 연결을 학습된 저차원 매니폴드를 따라 여러 내부 정보 스트림을 라우팅하도록 확장합니다. Transformer++ 스타일 모델의 단일 잔차 스트림을 여러 협조하는 스트림으로 일반화한 것입니다. 발표 시점에서 결과는 **독립적인 재현을 기다리는 중**으로 표시되어 있습니다.

**MIRAS**
Google Research의 메모리 증강 훈련 프레임워크로, 메모리가 추론 시에 업데이트되는 훈련 가능한 신경 모듈인 Titans 같은 아키텍처를 위한 레시피, 안정성 보장, 학습 동역학을 제공합니다. MIRAS는 메모리 모듈이 발산하지 않으면서 "추론하면서 학습"을 실용적으로 만드는 프레임워크입니다.

**MoE (Mixture of Experts, 전문가 혼합)**
주어진 입력에 대해 모델의 "두뇌"의 일부만 활성화되는 모델 아키텍처. 모든 부분이 매번 실행되지 않기 때문에 매우 큰 모델을 만들면서도 빠른 속도를 유지할 수 있습니다.

### O

**Obsidian**
노트를 자신의 컴퓨터에 일반 텍스트 파일로 저장하고 서로 연결하여 개인 지식 베이스를 만들 수 있게 해 주는 노트 앱.

**Org Graph / Work Graph (조직 그래프 / 작업 그래프)**
Yash Thakker의 2026년 7월 explainx.ai 가이드에 나오는, graph engineering의 두 그래프 대상: *org graph*는 어떤 에이전트가 존재하는지, 각각이 무엇을 위한 것인지, 어떤 위임 엣지가 허용되는지를 나타내는 안정적인 차트이며; *work graph*는 특정 작업이 낳고, 실행하고, 폐기하는 일시적인 작업 분해입니다. 회사의 조직도와, 프로젝트 하나를 위해 모였다가 끝나면 해산하는 임시 작업 그룹의 관계와 같습니다. **Graph Engineering** 참조; 14장.

**Outcomes (Anthropic)**
에이전트가 루브릭이 충족될 때까지 자신의 context window와는 별도의 context window에서 실행되는 채점자에 대항해 반복하는, 퍼블릭 베타 매니지드-에이전트 프리미티브 (Anthropic, 2026년 5월 6일). Ralph-loop / CATTS 불확실성-유도 반복 패턴을 API 계약으로 제품화합니다: 호출자가 루브릭을 쓰고, 기반이 에이전트를 대신해 반복-그리고-채점 루프를 실행하며, 수렴된 결과만 호출자에게 돌아갑니다.

**Outer Loop (아우터 루프)**
에이전트가 이너 실행 루프 (조사, 구현, 테스트/검증, 보고)를 실행하는 동안 인간이 지키는 판단 계층. Addy Osmani의 2026년 7월 후속작 "Own the Outer Loop"에서 나왔으며, 이를 세 기둥 —— Quality (에이전트가 행동하기 전에 실행되는 점검들의 back-pressure), Verdict ("작업이 우리의 의존 시스템에 들어가기 전에 우리가 내리는 최종 결정"), Answerability ("누군가 묻는다면, 나는 왜인지 설명할 수 있다는 보장") ——로 구조화합니다. Osmani는 이를 과잉 위임하는 세 가지 실패 모드를 명명합니다: cognitive debt (문제를 어떻게 푸는지에 대한 당신의 이해의 침식), cognitive surrender (AI가 주는 것을 맹목적으로 받아들이는 것), orchestration tax (당신의 판단이 감당할 수 있는 것보다 더 많은 에이전트를 띄우는 것). **Loop Engineering**과 **Generator-Evaluator Split**의 짝: 루프는 그 주위의 아우터 루프만큼만 좋습니다. 13장 참조.

### P

**Progressive Disclosure (점진적 공개)**
필수 정보만 먼저 보여 주고 필요할 때 더 자세한 내용을 드러내는 디자인 원칙. FAQ 페이지처럼 질문이 보이고, 실제로 필요한 답만 클릭으로 펼쳐 봅니다.

**Prompt Engineering (프롬프트 엔지니어링)**
가능한 최선의 응답을 얻을 수 있도록 AI 모델에 지시문을 작성하는 기술. 표현의 작은 변화가 매우 다른 결과를 낳을 수 있습니다.

### R

**RAG (Retrieval-Augmented Generation, 검색 증강 생성)**
AI가 답하기 전에 외부 출처에서 관련 정보를 찾아보고, 훈련 시 외운 내용에만 의존하지 않고 실제 데이터에 근거한 응답을 하는 기술.

**Routines (Claude Code)**
Anthropic의 2026년 4월 Claude Code용 클라우드 네이티브 하네스 프리미티브. 에이전트 워크플로우는 사용자의 머신이 아닌 Anthropic 클라우드에서 실행되며, 스케줄, API 호출 또는 GitHub 이벤트로 트리거할 수 있습니다. Routines는 자체 호스팅 cron+daemon 패턴을 매니지드 기반으로 일반화하며 티어별 쿼터(Pro 5/일, Max 15/일, Team/Enterprise 25/일)를 갖추고 사용자의 노트북이 오프라인일 때도 계속 작동합니다.

### S

**Safety-Tiered Distribution (안전 등급별 배포)**
하나의 모델 패밀리를, 가중치가 아니라 안전장치 수준과 배포 게이트가 다른 병렬 등급들로 출시하는 것. 참조 사례는 Anthropic의 2026년 6월 쌍입니다: **Claude Fable 5** (이중 용도 안전 조치를 갖춘 퍼블릭 GA, `stop_reason`으로서의 거부 포함)와 **Claude Mythos 5** (안전장치가 해제된 동일한 기반 가중치로, 검증된 Glasswing 연합에만 게이트됨). 이는 GPT-5.5 Trusted Access for Cyber처럼 벤더가 고른 접근 등급과 대비되며 —— 2026년 중반 기준으로는 GPT-5.6의 행정명령-게이트 프리뷰처럼 정부가 부과한 등급과도 대비됩니다. 이것이 인코딩하는 트레이드오프: 능력과 안전이 서로에게서 언바들되어, 당신이 누구인지 (검증된 조직인지 공개 사용자인지)가 모델이 무엇을 할 수 있는지가 아니라 어떤 안전장치 등급에 도달하는지를 결정합니다.

**Self-Hosted Sandbox (자체 호스팅 샌드박스)**
Anthropic이 2026년 5월 19일 (Code with Claude London) 퍼블릭 베타로 출시한 Managed Agents 배포 형태. 에이전트 루프 —— 오케스트레이션, context 관리, 오류 복구 ——는 Anthropic의 인프라에 남고, 도구 *실행*은 고객 자신의 환경이나 매니지드 샌드박스 제공자 (Cloudflare, Daytona, Modal, Vercel이 퍼스트파티로 지원됨)로 옮겨갑니다. Managed Agents를 "완전히 Anthropic이 호스팅"에서 "Anthropic이 오케스트레이션하고, 고객의 경계를 존중"으로 재프레이밍합니다 —— harness 엔지니어는 완전한 자체 호스팅과 완전한 매니지드 사이에서 선택하는 대신, 루프의 어느 조각이 어디에 사는지를 층별로 고릅니다.

**Self-RAG**
RAG의 한 종류로, AI가 자신이 가져온 정보와 생성한 답변의 품질을 평가하여 추가 검색이 필요한지 또는 응답을 수정해야 하는지를 결정한 후 최종 결과를 제공합니다.

**Session-hour pricing (세션 시간당 과금)** (*agent-runtime-hour pricing*으로도 보도)
오케스트레이터 자리 — 에이전트 루프가 실행되는 기반 — 를 추론과 별도로 계량하는 과금 모델. Anthropic Managed Agents가 2026년 4월 8일 처음 상용 도입했습니다. SiliconANGLE 출시 보도에 따르면 표준 토큰 요율에 더해 에이전트 런타임 시간당 8센트입니다. 시간당 수치는 Anthropic의 1차 문서에 기재되어 있지 않으며 2차 테크 프레스에서 인용된 것입니다. 주목할 점은 이것이 "루프가 어디에서 실행되는가"의 비용에 숫자를 붙인 **첫 번째 벤더 프리미티브**라는 점이며, "루프가 무엇을 생각하는가"의 비용과 구별됩니다. 정확한 표현은 1차 문서(*sessions* 사용)와 테크 프레스 보도(*agent runtime hour* 사용) 사이에서 다르지만 둘 다 같은 계량 표면을 가리킵니다.

**Skill (AI Agent Skill)**
AI 에이전트가 호출할 수 있는 재사용 가능하고 패키지화된 능력 — "이 PR을 리뷰하라"나 "데일리 리뷰를 실행하라" 같은 특정 작업을 위한 레시피와 같습니다.

**Stateless MCP (상태 비저장 MCP)**
2026-07-28 MCP Release Candidate에서 도입되어 (2026년 5월 21일 확정) 2026-07-28 사양 (2026년 7월 28일)에서 최종 출시된 아키텍처 전환: 프로토콜 코어는 더 이상 `initialize` / `initialized` 핸드셰이크나 `Mcp-Session-Id` 헤더를 쓰지 않습니다. 클라이언트 메타데이터는 모든 요청에서 `_meta` 안에 실려 다니므로, 어떤 MCP 요청이든 어떤 서버 인스턴스에든 도달할 수 있습니다 —— sticky routing도, 공유 세션 저장소도 없습니다. 2025년 Streamable HTTP 채택과 함께 표면화된 수평-스케일링 마찰을 해소합니다. *stateful* 전환을 촉발했던 durable-state 프리미티브들 (SEP-1686 Tasks, AgentCore 양방향 런타임)은 모든 요청에 구워 넣어지는 대신, 확장으로서 상태 비저장 코어 위에 재구현됩니다. 상태 비저장 코어에 stateful 작업이 얹힌 것이지, 끝까지 stateful인 것이 아닙니다.

**Skill Graph (스킬 그래프)**
AI 에이전트가 사용할 수 있는 모든 스킬의 지도. 스킬들이 서로 어떻게 관련되어 있는지, 각 스킬이 언제 트리거되어야 하는지를 포함합니다.

**Skill Supply-Chain Attack (스킬 공급망 공격)**
스킬 레지스트리나 마켓플레이스를 통해 배포되는 악성 또는 트로이 목마화된 에이전트 스킬. 2026년을 정의하는 메커니즘은 time-of-check-to-time-of-use 간극입니다: 정적 스캐너는 *제출된 패키지 스냅샷*을 검증하지만, 외부 콘텐츠를 가져오거나 —— 숨겨진 페이로드를 풀거나 —— 하는 스킬은 에이전트 런타임에 검증 이후 행동을 바꿀 수 있습니다. AIR의 2026년 6월 공개는 단 하나의 가짜 스킬 뒤에 외부 URL을 숨겨 이런 방식으로 약 26,000개의 에이전트를 탈취했고, "Cloak and Detonate" 연구 (2026년 7월)는 여덟 개의 스캐너를 상대로 90% 넘는 시간 동안 회피가 성공한다는 것을 보였으며, 대응책 방향으로 런타임 행동 탐지 (2% 오탐률에서 97%)를 제시했습니다. 이 교훈은 MCP의 그것을 반영합니다 (**MCP** 참조): **Progressive Disclosure** (**Progressive Disclosure** 참조)와 레지스트리-스케일 배포가 스킬 파일을 공격 표면으로 만들고 나면, 신뢰는 publish 시점 스캐닝에서 런타임 컨테인먼트로 옮겨가야 합니다.

**System Prompt (시스템 프롬프트)**
당신의 대화가 시작되기 전에 AI 모델에 주어지는 숨겨진 지시문으로, 모델의 역할, 규칙, 행동을 설정합니다. 직원이 첫 출근 전에 읽는 직무 기술서와 같습니다.

### T

**Task Budget (태스크 버짓)**
Anthropic이 Claude Opus 4.7에서 도입한 하네스 프리미티브(2026년 4월, beta 헤더 `anthropic-beta: task-budgets-2026-03-13`). 호출자는 **에이전트 루프 전체**(사고, 도구 호출, 도구 결과, 최종 출력)에 대한 권고적 토큰 예산을 선언하고, 모델은 작업하는 동안 카운트다운을 받아 한 단계가 검색, 추론, 종합에 얼마나 더 들일 가치가 있는지 결정합니다. 모델에 보이지 않는 하드 캡인 `max_tokens`와는 다릅니다. 예산은 강제가 아닌 권고적이며, 빠듯한 예산에서 거부 응답으로 퇴화하는 것을 막기 위해 최소 20K 토큰이 보장됩니다. Task budgets는 "각 단계에 대해 얼마나 깊이 생각해야 하는가"를 수동 조정 매개변수가 아닌 **매니지드 컨트랙트**로 표면화한 첫 번째 벤더 프리미티브입니다.

**Temporal Policies (템포럴 정책)**
2026년 8월 6일 Amazon Bedrock AgentCore에서 AWS가 출시한, 게이트웨이가 강제하는 인가 프리미티브. 평범한 정책이 "이 에이전트가 이 호출을 해도 되는가"를 묻는 곳에서, temporal policy는 그 호출을 같은 세션 안의 에이전트의 *이전* 행동들에 대해 평가합니다 —— 결정론적으로, deny-by-default로, 완전히 로그되며, 에이전트 코드 바깥에서 이루어지므로 어떤 prompt나 모델의 결정도 이를 말로 구슬려 넘어갈 수 없습니다. 정책은 AI 에이전트를 위해 목적에 맞게 만들어진 새로운 Apache-2.0 오픈소스 정책 언어인 **Dogwood**로 작성됩니다. 명명된 용례는 지시문으로는 막을 수 없는 실패 모드들입니다: 데이터-조작 방지 (에이전트가 앞으로 전달하는 값이 이전 호출이 실제로 반환한 것과 일치해야 함), 누적 세션 비용 상한, 그리고 특권 행동 전에 인간의 승인 단계를 요구하는 워크플로우 시퀀싱. 단일-행동 하드 캡 (AgentCore Payments, 2026년 5월)을 하나의 호출에서 세션 이력으로 일반화한 것입니다 —— harness 설계의 Authority 축이 stateful 강제 계층을 얻은 것입니다.

**Titans**
Google Research의 2026년 4월 아키텍처 제품군. 메모리는 외부 벡터 저장소나 고정된 어텐션 윈도우가 아닌, 추론 시 경사 하강법으로 자신을 업데이트하는 훈련 가능한 신경 모듈입니다. 비교 가능한 매개변수 수에서 Titans는 장거리 회상과 멀티홉 추론 벤치마크에서 Mamba-2, Gated DeltaNet, Transformer++을 능가하는 것으로 보고되어, "컨텍스트"와 "파인튜닝" 사이의 경계를 흐립니다.

**Token (토큰)**
AI 모델이 읽고 쓰는 기본 단위 — 영어로는 대략 단어의 4분의 3에 해당합니다. 모델은 토큰 단위로 사고하며, 가격과 컨텍스트 한도는 토큰으로 측정됩니다.

**Tool Use / Function Calling (도구 사용 / 함수 호출)**
AI 모델이 텍스트 생성뿐 아니라 외부 행동 — 웹 검색, 코드 실행, API 호출 — 을 트리거할 수 있는 능력.

### V

**Vector Database (벡터 데이터베이스)**
임베딩을 저장하고 검색하기 위해 전용으로 설계된 데이터베이스. 수백만 항목 중에서 가장 유사한 항목을 빠르게 찾을 수 있게 합니다. 대부분의 RAG 시스템의 엔진입니다.

### W

**Wikilink**
Obsidian 같은 도구에서 사용되는 이중 대괄호 링크(예: `[[노트 제목]]`). 한 노트를 다른 노트에 연결하여 연결된 지식의 웹을 만듭니다.

### X

**x402**
기계 간 인밴드 스테이블코인 결제를 위해 HTTP 상태 코드 402 ("Payment Required")를 되살리는 오픈 프로토콜로, 에이전트-대-리소스 거래에 쓰입니다. Coinbase가 창안했으며; AWS AgentCore Payments (2026년 5월 7일)에서 첫 하이퍼스케일러-매니지드 구현이 나왔습니다. 도구 계층에 대한 MCP의 "가치 계층" 유사물입니다 —— MCP가 에이전트가 API에 도달하는 방식을 표준화한다면, x402는 에이전트가 그 API에 대금을 지불하는 방식을 표준화합니다. AWS의 지지 이전의 견인력: 2026년 4월 말까지 69,000개의 활성 에이전트와 누적 약 5천만 달러의 거래량.
