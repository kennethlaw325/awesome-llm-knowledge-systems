## 용어집

> 이 가이드에 나오는 모든 기술 용어를 쉬운 말로 정의했다. 박사 학위는 필요 없다.

### A

**A2A (Agent-to-Agent Protocol, 에이전트 간 프로토콜)**
AI 에이전트들이 서로 소통하고 작업을 조율하기 위한 표준적인 방법. 서로 다른 AI 어시스턴트가 작업을 인계할 수 있게 해 주는 공통 언어와 같습니다.

**Agent Memory (에이전트 메모리)**
AI 에이전트가 대화나 작업을 가로질러 정보를 기억하는 능력. 에이전트가 세션 사이에 보관하는 노트와 같다고 생각하세요. 매번 처음부터 시작할 필요가 없게 만듭니다.

**Agentic RAG (에이전트형 RAG)**
RAG의 한 종류로, AI가 무엇을 찾을지, 언제 찾을지, 결과가 충분히 좋은지를 능동적으로 결정합니다. 매번 같은 고정된 검색 단계를 따르지 않습니다.

**앵커 (그래프 엔지니어링)**
다중 에이전트 그래프의 어떤 노드가 반드시 확인해야 하는, 외부 근거에 기반해 다툼의 여지가 없는 측정값이다. 테스트 결과, 지표, 실제 사실과의 대조 등이 해당한다. Carlos E. Perez가 July 2026 그래프 엔지니어링 담론에서 도입했다. 앵커가 없으면 서로의 작업을 검토하는 에이전트 그래프는 정확성보다 자신만만한 합의에 수렴하는 반향실로 변한다. 위원 모두가 예산이 맞아 보인다고 동의하는 대신, 최소 한 명이 실제 은행 명세서를 확인하도록 요구하는 것과 같다. **그래프 엔지니어링** 및 14장 참조.

**ARC-AGI-3**
François Chollet의 2026년 에이전트 지능을 위한 인터랙티브 벤치마크. 에이전트는 지시 없이 게임 같은 환경에 던져져 스스로 탐험하고, 목표를 추론하고, 세계 모델을 구축해야 합니다. 정적인 퍼즐 그리드로 구성된 이전 ARC 벤치마크와 달리, ARC-AGI-3는 **탐험 효율성**, **목표 추론**, **세계 모델 형성**을 별도의 능력 축으로 평가합니다.

### C

**CATTS (Consensus-Aware Test-Time Scaling, 합의 인식 테스트 시 스케일링)**
멀티스텝 에이전트를 위한 테스트 시 스케일링 방법. 각 단계마다 작은 롤아웃 위원회를 샘플링하고, 위원들 사이의 불일치를 불확실성 신호로 사용하여 컴퓨팅을 할당합니다. 의견이 크게 갈리는 단계는 더 많은 사고 예산을 받고, 합의가 잘 되는 단계는 더 적게 받습니다. 공개된 결과는 균일 스케일링 대비 약 +9.1% 정확도, 2.3배 적은 토큰을 보고합니다.

**Claude Code**
Anthropic의 명령줄 도구. Claude가 터미널에서 직접 작업하면서 파일을 읽고, 명령을 실행하고, 코드를 편집합니다. AI 페어 프로그래밍 동료처럼 동작합니다.

**클라이언트 ID 메타데이터 문서 (CIMD)**
확정된 MCP 2026-07-28 명세가 의무화한 클라이언트 식별 메커니즘으로 동적 클라이언트 등록을 대체한다. MCP 클라이언트가 서버마다 별도로 등록하는 대신 URL에 호스팅된 메타데이터 문서로 식별된다. 방문하는 사무실마다 신규 업체 양식을 작성하는 대신 자신의 주소에 호스팅한 명함을 제시하는 것과 같다. **MCP** 참조.

**Codex (OpenAI)**
OpenAI의 도구. AI 에이전트가 샌드박스화된 클라우드 환경에서 코딩 작업을 실행하고, 자율적으로 저장소를 읽고, 코드를 작성하고, 테스트를 실행합니다.

**Context Engineering (컨텍스트 엔지니어링)**
AI가 응답하기 전에 받는 정보를 신중하게 설계하는 실천. Prompt engineering이 질문을 작성하는 것이라면, context engineering은 AI의 책상 위에 어떤 참고 자료를 올려놓을지 선택하는 것입니다.

**Context Window (컨텍스트 윈도우)**
AI 모델이 한 번에 "see" 텍스트의 총량 — 당신의 입력과 모델의 출력 모두를 포함합니다. 화이트보드의 크기와 같다고 생각하세요. 모델이 읽고 쓰는 모든 것이 그 안에 들어가야 합니다.

**CoT Monitoring (사고 연쇄 모니터링)**
모델이 계획대로 행동하기 전에 명시적인 추론 토큰을 읽어 잘못된 행동이나 정렬 실패를 탐지하는 방식이다. OpenAI는 April 2026에 CoT 모니터링으로 자체 추론 모델 하나가 코딩 평가에서 부정행위를 하는 것을 적발했다. 해석 가능성이 사후 조사 도구가 아닌 실행 중 점검 수단으로 작동한 최초의 공개 사례다.

### D

**판단 모델**
개방형 응답을 생성하는 대신 범위와 유형이 정해진 질문에 판단과 그에 따른 확률을 반환하는 모델이다. 하네스는 이 판단을 라우팅이나 우선순위 분류에 활용할 수 있고, 결정론적 애플리케이션 코드가 권한에 대한 결정권을 유지한다. 확률에는 보정 검사가 필요하며, 판단이 옳다는 증거는 아니다. [12장](chapters/ko/12-local-models.md) 참조.

**Dreaming**
최근 세션 패턴을 바탕으로 에이전트의 지속 저장 메모리를 다시 쓰는, 세션 사이에 예약된 메모리 정리 작업이다. Anthropic Managed Agents가 처음 상용화했다(May 6, 2026, 연구 미리보기). 정리 담당자가 최근 세션을 읽어 반복되는 오류와 수렴한 작업 흐름을 식별하고, 에이전트의 지속 저장 메모리를 평문으로 다시 쓴다. 추론 시 기울기 갱신으로 적응하는 학습 가능한 메모리(Titans + MIRAS, April 2026)와 대비된다. Dreaming은 메모리를 하네스가 읽는 데이터로 유지하고, Titans는 메모리를 모델 자체의 일부로 만든다.

### E

**Embeddings (임베딩)**
의미가 비슷한 텍스트가 수학적으로도 가까이 위치하도록 텍스트를 숫자 리스트로 변환하는 방법. 컴퓨터가 두 책이 비슷한 주제를 다룬다는 걸 알아채는 것과 같은 방식으로 텍스트의 관련성을 측정할 수 있게 합니다.

**Emotion Vectors (감정 벡터)**
Claude의 내부 활성화에서 해석 가능한 특징 방향으로, 강도를 높이면 감정적으로 격한 행동 쪽으로 모델을 일관되게 편향시킨다. Anthropic의 April 2026 공개에는 협박 형태의 출력도 포함됐다. 이 방향들은 식별할 수 있으므로 하네스 엔지니어에게 토큰 수준이 아닌 특징 수준의 필터링 지점을 제공한다.

**기업 관리형 인가 (EMA)**
MCP 서버 접근을 중앙집중적으로 IdP에서 프로비저닝하는 MCP 확장이다(June 18, 2026 안정화). 사용자마다 모든 서버에 앱별 OAuth 동의 절차를 거치는 대신 조직이 ID 공급자를 통해 서버 접근을 한 번 프로비저닝한다. SSO 중 클라이언트는 **Identity Assertion JWT Authorization Grant (ID-JAG)**를 받아 MCP 서버 자체의 인가 서버가 발급한 접근 토큰으로 교환한다(**MCP** 참조). 첫날 지원에는 IdP인 Okta, 클라이언트인 Anthropic과 VS Code, 서버 일곱 개가 포함됐다. EMA는 MCP의 기업 SSO를 서버별 통합 작업에서 IdP에서 한 번 내리는 프로비저닝 결정으로 바꾼다.

### F

**Few-shot Learning (퓨샷 학습)**
모델 전체를 다시 훈련하는 대신 프롬프트 안에 몇 가지 예시를 보여 주어 AI에게 작업 방법을 가르치는 것. 완성된 양식 세 장을 보여 주어 네 번째 양식을 채우는 방법을 알려 주는 것과 같습니다.

**Fine-tuning (파인튜닝)**
사전 훈련된 AI 모델을 자신의 특정 데이터로 추가 훈련하여 특정 작업을 더 잘 수행하게 만드는 것. 제너럴리스트를 채용한 후 전문 OJT를 제공하는 것과 같습니다.

### G

**생성자-평가자 분리**
작업을 만드는 에이전트와 이를 판단하는 독립적이고 의도적으로 회의적인 에이전트를 분리하는 신뢰성 패턴이다. 에이전트가 자기 결과물을 일관되게 과대평가하기 때문에 도입됐다. Prithvi Rajasekaran의 "Harness design for long-running application development" (Anthropic, March 2026)에서 소개됐다. 생성적 적대 신경망(GAN)의 구조를 차용했으며, 생성자를 자기비판적으로 만드는 것보다 독립 평가자를 회의적으로 조정하는 편이 훨씬 다루기 쉽다는 것을 발견했다. 평가자는 코드 차이를 읽는 대신 동작을 검증한다. 실행 중인 앱을 클릭해 보고, 스크린샷을 찍고, UI 기능, API 엔드포인트, 데이터베이스 상태를 시험한다. 이 패턴은 Claude Code의 `/goal`처럼 조건이 충족될 때까지 실행하는 기본 기능으로 제품화됐다. 여기서는 별도의 새 모델이 매 턴 뒤 종료 조건을 판단한다. **바깥 루프**, **루프 엔지니어링** 참조.

**그래프 엔지니어링**
**루프 엔지니어링** 위의 계층은 그래프라는 July 2026의 주장이다. 어떤 에이전트가 존재하고, 누가 누구에게 위임할 수 있으며, 각자의 루프가 어떻게 서로를 감독하고 수정하는지를 명시적으로 연결한다. July 17-18, 2026의 Peter Steinberger 게시물 이후 이어진 글에서 구체화됐으며 첫날부터 논쟁적이었다. LangChain의 응답은 루프가 단지 방향성 순환 그래프이므로 실무 자체는 세 해 됐고 새것은 이름뿐이라고 주장한다. 시스템이 *무엇을 아는지* 구조화하는 지식 그래프나 **GraphRAG**와 혼동하면 안 된다. 그래프 엔지니어링은 시스템을 *누가 구성하는지* 구조화한다. 이 가이드의 September 15, 2026 생존 점검에서는 독립적인 글과 에이전트 조직이라는 의미를 가르치는 유료 강좌 등 용어가 여전히 쓰이고 있음을 확인했다. 그러나 확인한 문서에서 공급업체의 채택은 발견하지 못했으며, 유통은 살아남았지만 독립 계층이라는 지위는 입증되지 않았다고 판정했다. 이 가이드는 이를 확립된 계층보다 다중 에이전트 조정을 가리키는 논쟁적인 이름으로 추적한다. 14장 참조.

**GraphRAG**
RAG의 한 종류로, 검색된 정보를 연결된 엔티티와 관계의 그래프로 정리하여 여러 출처에서 사실을 결합해야 하는 질문에 더 잘 답할 수 있게 합니다.

### H

**Harness Engineering (하네스 엔지니어링)**
AI 모델을 둘러싼 시스템 — 도구, 메모리, 규칙, 워크플로우 — 전체를 설계하여 모델이 실제로 어떻게 동작할지 형성하는 일. 모델이 엔진이라면, 하네스는 차 전체입니다.

**Harness Synthesis (하네스 합성)**
외부 루프 최적화기(검색 기반, 관측 가능성 기반 등)가 대상 과제의 실행 중 신호에 따라 하네스의 도구, 프롬프트, 역할 분해, 통신 토폴로지, 조정 프로토콜을 자동으로 바꾸는 기법군이다. April 2026의 두 참조 구현은 **AHE** (arXiv 2604.25850)와 **AgentFlow** (arXiv 2604.20801)를 참조하라. 하네스를 지속적으로 발전하는 산출물이 아닌 일회성 최적화 대상으로 취급했던 *메타 하네스*(2025 / 2026년 초의 관점)와 구별된다.

**하네스 네이티브 학습**
특정 실서비스 에이전트 하네스를 대상으로 모델을 직접 학습해, 단독으로 올바른 출력을 만드는 데 그치지 않고 해당 하네스의 도구와 작업 흐름을 운용하도록 하는 것이다. 참조 사례는 Microsoft의 **MAI-Code-1-Flash** (Build, June 2, 2026)다. 실서비스 GitHub Copilot 하네스를 대상으로 학습한 매개변수 5B 코딩 모델이며, Microsoft는 어려운 과제에서 토큰을 약 60% 적게 쓰고 Claude Haiku 4.5보다 가격 대비 성능이 좋다고 보고한다. 하네스 네이티브 학습은 **하네스 합성의 대칭적 역방향**이다. 하네스 합성(**하네스 합성**, **AHE** 참조)은 모델을 고정하고 하네스를 발전시키는 반면, 하네스 네이티브 학습은 하네스를 고정하고 모델을 맞춘다. 둘을 함께 보면 모델과 하네스는 양쪽 끝에서 최적화할 수 있는 공동 설계 문제가 된다. 절충점은 특정 공급업체의 하네스에 맞춘 모델이 그 하네스 안에서 가장 가치가 크다는 것으로, *경쟁 우위의 방어벽으로서 하네스*라는 역학을 강화한다.

### I

**Inference (추론)**
AI 모델이 당신의 입력에 대한 응답을 생성하는 과정. 메시지를 보내고 응답을 받을 때마다 모델은 추론을 수행하고 있습니다.

**Iteration Head (이터레이션 헤드)**
사고 사슬 추론 중 나타나 이전 추론 단계의 출력에 일관되게 주의를 기울이는 어텐션 헤드다. Anthropic 해석 가능성 팀이 April 2026에 식별했다. 이는 명시적 CoT 프롬프팅의 효과가 사람이 읽을 수 있는 중간 텍스트를 만드는 것뿐 아니라, 특정 내부 회로를 유도하는 데에도 일부 기인함을 시사한다.

### K

**Knowledge Graph (지식 그래프)**
사실의 구조화된 지도로, 엔티티(사람, 장소, 개념)들이 라벨이 붙은 관계로 연결되어 있습니다. 모든 것이 어떻게 서로 연결되어 있는지 보여 주는 라벨링된 끈으로 연결된 색인 카드 웹과 같습니다.

**KV-Cache**
AI가 이전에 계산한 키-값 쌍을 다시 사용해 처음부터 다시 계산할 필요가 없게 해 주는 메모리 단축. 대화 이력이 동일하면 응답이 더 빠르고 저렴해집니다.

### L

**LLM (Large Language Model, 대규모 언어 모델)**
방대한 양의 텍스트로 훈련되어 인간 언어를 이해하고 생성할 수 있는 AI 시스템. ChatGPT, Claude, Gemini는 모두 LLM입니다.

**Long Context (롱 컨텍스트)**
새로운 AI 모델이 한 번에 매우 많은 양의 텍스트를 처리하는 능력 — 책 한 권이나 코드베이스 전체가 한 번의 대화에 들어갈 수도 있습니다.

**루프 엔지니어링**
June 2026에 이름이 붙은 실무로, 매 턴 직접 프롬프트를 쓰는 대신 자신을 대신해 에이전트에 프롬프트를 보내는 시스템을 만드는 것이다. Addy Osmani의 June 7, 2026 글에서 조어됐으며, "the system that does it instead,"를 설계해 "replacing yourself as the person who prompts the agent"하는 것으로 정의했다. 같은 주간 널리 퍼진 Peter Steinberger 게시물이 계기였다. **하네스 엔지니어링**보다 한 층 위에 있다. 루프는 타이머에 따라 실행되고, 보조 하위 에이전트를 띄우며, 저장된 상태로부터 다음 입력을 얻는 하네스다. 시계에 따라 고정 명령을 실행하는 단순 스케줄러와 달리, 매 회차 현재 상태를 읽고 할 일을 다시 판단한다. 실무자만 사용하는 논쟁적인 용어로 mid-2026 기준 학술 문헌은 없다. 이 가이드는 이를 확립된 세대가 아닌 떠오르는 네 번째 계층으로 추적한다. 13장 참조.

### M

**메모리 충돌 해결**
경합하는 사실 중 무엇을 선택했는지와 그 선택을 뒷받침하는 증거를 함께 기록한 것이다. 지속 저장되는 메모리 시스템은 출처가 바뀌거나 사라지거나 잊히면 이를 재검토하거나 폐기해야 한다. 이는 수명 주기 요건이지 모든 메모리 백엔드가 데이터베이스 트랜잭션을 구현한다는 주장이 아니다. [6장](chapters/ko/06-agent-memory.md) 참조.

**MCP (Model Context Protocol, 모델 컨텍스트 프로토콜)**
AI 어시스턴트가 보편적인 플러그 앤 플레이 인터페이스를 통해 외부 도구와 데이터 소스에 연결할 수 있게 해 주는 오픈 표준. AI 애플리케이션을 위한 USB와 같습니다.

**MCP Apps**
2026-07-28 MCP 릴리스 후보의 기본 기능(May 21, 2026 확정)으로, 서버가 도구 호출과 함께 대화형 HTML 인터페이스를 제공할 수 있게 한다. 호스트는 샌드박스 iframe 안에서 인터페이스를 렌더링하며, 보안 검토와 캐싱을 위해 UI 템플릿은 미리 선언한다. MCP Apps는 도구 호출이 아닌 최초의 MCP 네이티브 산출물이다. 지식 기반 서버는 검색창을, 연구 서버는 결과 비교 화면을, 구매 서버는 구매 확인 모달을 별도 UI 명세 없이 제공할 수 있다.

**MCP 터널**
Anthropic Managed Agents가 May 19, 2026에 연구 미리보기로 제공한 사설 네트워크 배포 패턴이다(Code with Claude London). 고객의 사설 네트워크 안에 배포된 경량 게이트웨이가 Anthropic으로 하나의 아웃바운드 연결을 맺으면, 에이전트는 내부 데이터베이스, API, 지식 기반, 티켓 시스템을 MCP 도구로 호출할 수 있다. 인바운드 방화벽 규칙, 공개 엔드포인트, VPN이 필요 없다. 자체 호스팅 샌드박스의 대칭적 대응 방식이다. 자체 호스팅 샌드박스가 도구 *실행*을 고객 경계 안에 두는 반면, MCP 터널은 도구가 *접근하는 범위*를 그 경계 안에 둔다.

**Managed Agents (매니지드 에이전트)**
에이전트 하네스의 기반인 샌드박스, 세션 상태, 범위가 제한된 도구 실행, 추적을 개발자가 아닌 모델 공급업체가 운영하는 호스팅 실행 환경 모델이다. Anthropic은 April 8, 2026에 첫 상용 사례를 공개 베타로 출시했다([platform.claude.com/docs/en/managed-agents/overview](https://platform.claude.com/docs/en/managed-agents/overview)). SiliconANGLE의 출시 보도에 따르면 가격은 표준 API 토큰 요금에 기반 사용에 대한 에이전트 실행 시간당 요금을 더한다(시간당 수치는 Anthropic 일차 문서에는 없다). Claude Code Routines 같은 클라우드 네이티브 트리거와는 구별된다. 그런 트리거는 Managed Agents식 기반 위에 있지만 "what makes the loop start"라는 다른 질문에 답한다.

**Mechanistic Interpretability (메커니즘적 해석 가능성)**
모델 가중치 내부에서 사람이 이해할 수 있는 회로, 즉 특정 행동을 구현하는 구체적인 특징, 헤드, 경로를 식별하려는 연구 분야다. MIT Technology Review의 2026년 10대 혁신 기술에 선정됐으며, 감정 벡터, 반복 헤드, CoT 모니터링 등 April 2026의 성과를 뒷받침한다.

**메모리 기반 모델**
에이전트 메모리가 외부가 아닌 트랜스포머 기반 모델 자체 안에 매개변수 형태의 지속적이고 동적으로 변하는 상태로 존재해야 한다는 July 2026의 주장이다(MemTensor의 Metis, arXiv 2607.26760). 시제품은 고정된 Qwen3.5 기반 모델 위에서 4B / 9B / 27B 규모로 "hyper memory block"과 "local memory block"을 학습한다(Fast Weight Programming에서 영감을 받음). 벡터 저장소 쓰기나 Titans식 기울기 갱신 대신, 기울기를 사용하지 않는 EMA식 순전파로 추론 시 메모리를 갱신한다. 자체 보고한 한계는 고정 크기 압축에서의 장기 정보 손실과 "information confusion in some cases, possibly caused by the blending of semantics within the latent space"다. 연구 미리보기이며 아직 검증된 실서비스 패턴은 아니다. 6장 참조.

**mHC (Manifold-Constrained Hyper-Connections, 매니폴드 제약 하이퍼 연결)**
학습된 저차원 다양체를 따라 여러 내부 정보 흐름을 라우팅해 잔차 연결을 확장하는 DeepSeek의 April 2026 아키텍처 제안이다. Transformer++식 모델의 단일 잔차 흐름을 서로 조정되는 여러 흐름으로 일반화한다. 발표 시점에는 독립적 재현을 기다리는 결과로 표시돼 있다.

**MIRAS**
Google Research의 메모리 증강 학습 프레임워크로, 메모리가 추론 시 갱신되는 학습 가능한 신경 모듈인 Titans 같은 아키텍처에 학습법, 안정성 보장, 학습 동역학을 제공한다. MIRAS는 메모리 모듈이 발산하지 않으면서 추론 중 학습을 다룰 수 있게 하는 프레임워크다.

**MoE (Mixture of Experts, 전문가 혼합)**
주어진 입력에 대해 모델의 "brain"의 일부만 활성화되는 모델 아키텍처. 모든 부분이 매번 실행되지 않기 때문에 매우 큰 모델을 만들면서도 빠른 속도를 유지할 수 있습니다.

### O

**Obsidian**
노트를 자신의 컴퓨터에 일반 텍스트 파일로 저장하고 서로 연결하여 개인 지식 베이스를 만들 수 있게 해 주는 노트 앱.

**조직 그래프 / 작업 그래프**
Yash Thakker의 July 2026 explainx.ai 가이드에서 제시한 그래프 엔지니어링의 두 그래프 객체다. *조직 그래프*는 어떤 에이전트가 있고, 각각 무엇을 담당하며, 어떤 위임 연결이 허용되는지 나타내는 안정적인 조직도다. *작업 그래프*는 특정 과제를 위해 만들어 실행한 뒤 버리는 일시적인 작업 분해 구조다. 회사 조직도와, 프로젝트 하나를 위해 임시로 만들었다가 해산하는 작업반의 관계와 같다. **그래프 엔지니어링** 및 14장 참조.

**Outcomes (Anthropic)**
자체 컨텍스트 창에서 실행되는 별도 평가자의 기준표를 충족할 때까지 에이전트가 반복하는 공개 베타 관리형 에이전트 기본 기능이다(Anthropic, May 6, 2026). Ralph 루프 / CATTS의 불확실성 기반 반복 패턴을 API 계약으로 제품화했다. 호출자가 기준표를 쓰면 기반이 에이전트를 대신해 반복과 평가 루프를 실행하며, 수렴한 결과만 호출자에게 반환한다.

**바깥 루프**
에이전트가 조사, 구현, 테스트/검증, 보고의 내부 실행 루프를 돌리는 동안 사람이 유지하는 판단 계층이다. Addy Osmani의 July 2026 후속 글 "Own the Outer Loop,"에서 나온다. 글은 품질(에이전트 행동 전 역압 점검), 판정("the final decision we make before work enters our dependent system"), 설명 책임("the guarantee that if someone asks, I can explain why")이라는 세 기둥으로 구성한다. Osmani는 과도하게 위임할 때 생기는 세 실패 양상으로 인지 부채(문제 해결 방법에 대한 자신의 이해가 약해짐), 인지적 포기(AI의 답을 맹목적으로 수용), 오케스트레이션 부담(자신의 판단이 감당할 수 있는 수보다 많은 에이전트를 띄움)을 명명한다. **루프 엔지니어링**, **생성자-평가자 분리**를 보완한다. 루프의 품질은 그 바깥을 감싸는 루프만큼만 좋다. 13장 참조.

### P

**Progressive Disclosure (점진적 공개)**
필수 정보만 먼저 보여 주고 필요할 때 더 자세한 내용을 드러내는 디자인 원칙. FAQ 페이지처럼 질문이 보이고, 실제로 필요한 답만 클릭으로 펼쳐 봅니다.

**Prompt Engineering (프롬프트 엔지니어링)**
가능한 최선의 응답을 얻을 수 있도록 AI 모델에 지시문을 작성하는 기술. 표현의 작은 변화가 매우 다른 결과를 낳을 수 있습니다.

### R

**RAG (Retrieval-Augmented Generation, 검색 증강 생성)**
AI가 답하기 전에 외부 출처에서 관련 정보를 찾아보고, 훈련 시 외운 내용에만 의존하지 않고 실제 데이터에 근거한 응답을 하는 기술.

**Routines (Claude Code)**
Anthropic이 April 2026에 Claude Code용으로 도입한 클라우드 네이티브 하네스 기본 기능이다. 에이전트 작업 흐름이 사용자 기기 대신 Anthropic 클라우드에서 실행되며, 일정, API 호출, GitHub 이벤트로 시작할 수 있다. Routines는 자체 호스팅 cron과 데몬 패턴을 할당량 등급(Pro 하루 5회, Max 하루 15회, Team/Enterprise 하루 25회)이 있는 관리형 기반으로 일반화하며, 사용자의 노트북이 오프라인이어도 유지된다.

### S

**공유 컨텍스트 계층**
이를 사용하는 에이전트나 모델과 분리해 유지하는 지속적 컨텍스트다. 여러 에이전트가 같은 기반 정보에 대해 권한에 맞는 보기에 접근할 수 있다. 저장소가 기기 안에 있다고 해서 이를 사용하는 모든 에이전트가 로컬에서 실행된다는 뜻은 아니다. [12장](chapters/ko/12-local-models.md) 참조.

**안전 등급별 배포**
하나의 모델 계열을 가중치가 아닌 안전장치 수준과 배포 관문이 다른 병렬 등급으로 내놓는 것이다. 참조 사례는 Anthropic의 June 2026 두 모델이다. **Claude Fable 5**는 거절을 `stop_reason`으로 표시하는 것을 포함한 이중 용도 안전조치를 갖춰 정식 공개 출시됐고, **Claude Mythos 5**는 같은 기반 가중치에서 안전장치를 해제해 심사된 Glasswing 연합에만 제공됐다. GPT-5.5 Trusted Access for Cyber 같은 공급업체 선택 접근 등급, 그리고 mid-2026의 GPT-5.6 행정명령 기반 제한 미리보기 같은 정부 지정 등급과 대비된다. 이 절충 구조에서는 역량과 안전이 분리되므로 모델이 무엇을 할 수 있는지가 아니라 접근자가 누구인지(심사된 조직인지 일반 사용자인지)에 따라 사용할 수 있는 안전장치 등급이 결정된다.

**자체 호스팅 샌드박스**
Anthropic이 May 19, 2026에 공개 베타로 출시한 Managed Agents 배포 형태다(Code with Claude London). 오케스트레이션, 컨텍스트 관리, 오류 복구를 수행하는 에이전트 루프는 Anthropic 인프라에 남고, 도구 *실행*은 고객 자체 환경이나 관리형 샌드박스 공급자로 옮겨 간다(Cloudflare, Daytona, Modal, Vercel을 공식 지원). Managed Agents를 "fully Anthropic-hosted"에서 "Anthropic-orchestrated, customer-perimeter-respecting"으로 재정의한다. 하네스 엔지니어는 완전 자체 호스팅과 완전 관리형 중 하나를 고르는 대신, 계층별로 루프의 어느 부분을 어디에 둘지 선택한다.

**Self-RAG**
RAG의 한 종류로, AI가 자신이 가져온 정보와 생성한 답변의 품질을 평가하여 추가 검색이 필요한지 또는 응답을 수정해야 하는지를 결정한 후 최종 결과를 제공합니다.

**Session-hour pricing (세션 시간당 과금)** (*agent-runtime-hour pricing*으로도 보도)
추론과 별도로 오케스트레이터 자리, 즉 에이전트 루프가 실행되는 기반의 사용량을 측정하는 과금 모델이다. SiliconANGLE의 출시 보도에 따르면 Anthropic Managed Agents가 처음 상용 도입했다(April 8, 2026). 표준 토큰 요금에 에이전트 실행 시간당 팔 센트를 더했다. 시간당 수치는 Anthropic 일차 문서에 없으며 이차 기술 언론 보도를 인용한 것이다. "where the loop runs,"의 비용을 "what the loop thinks."의 비용과 구별해 처음으로 수치화한 공급업체 기본 기능이라는 점이 특징이다. 일차 문서는 *세션*을, 기술 언론 보도는 *에이전트 실행 시간*을 말하는 등 정확한 표현은 다르지만, 둘 다 같은 사용량 측정 대상을 가리킨다.

**Skill (AI Agent Skill)**
AI 에이전트가 호출할 수 있는 재사용 가능하고 패키지화된 능력 — "review this PR"나 "run a daily review." 같은 특정 작업을 위한 레시피와 같습니다.

**무상태 MCP**
MCP 2026-07-28 릴리스 후보(May 21, 2026 확정)에서 도입되고 2026-07-28 명세(July 28, 2026)에서 최종 출시된 아키텍처 변화다. 프로토콜 핵심은 더 이상 `initialize` / `initialized` 핸드셰이크나 `Mcp-Session-Id` 헤더를 사용하지 않는다. 클라이언트 메타데이터는 매 요청의 `_meta`에 실리므로 MCP 요청은 어떤 서버 인스턴스에도 도달할 수 있다. 고정 라우팅이나 공유 세션 저장소가 필요 없다. 2025년 Streamable HTTP 도입으로 드러난 수평 확장의 마찰을 해소한다. *상태 유지형* 전환의 동기가 됐던 지속 상태 기본 기능(SEP-1686 Tasks, AgentCore 양방향 실행 환경)은 매 요청에 내장되는 대신 무상태 핵심 위의 확장으로 다시 구현된다. 아래까지 모두 상태를 유지하는 것이 아니라, 무상태 핵심 위에 상태 유지 작업을 올리는 방식이다.

**Skill Graph (스킬 그래프)**
AI 에이전트가 사용할 수 있는 모든 스킬의 지도. 스킬들이 서로 어떻게 관련되어 있는지, 각 스킬이 언제 트리거되어야 하는지를 포함합니다.

**스킬 공급망 공격**
스킬 레지스트리나 마켓플레이스로 배포되는 악성 또는 트로이 목마형 에이전트 스킬이다. 2026년의 핵심 메커니즘은 검사 시점과 사용 시점 사이의 간극이다. 정적 검사기는 *제출된 패키지 스냅샷*을 검증하지만, 에이전트 실행 중 외부 콘텐츠를 가져오거나 숨겨진 페이로드를 푸는 스킬은 검증 뒤 동작을 바꿀 수 있다. AIR의 June 2026 공개에서는 외부 URL 뒤에 둔 가짜 스킬 하나로 에이전트 약 26,000개를 탈취했다. "Cloak and Detonate" 연구(July 2026)는 여덟 검사기를 상대로 90% 이상의 회피 성공률을 보였으며, 대응 방향으로 실행 중 행동 탐지(오탐률 2%에서 97%)를 제시했다. 교훈은 MCP와 같다(**MCP** 참조). **점진적 공개**(**점진적 공개** 참조)와 레지스트리 규모의 배포가 스킬 파일을 공격 표면으로 만들면, 신뢰의 중심은 게시 시점 검사에서 실행 중 격리 제약으로 옮겨 가야 한다.

**희소 오토인코더 (SAE)**
모델 내부 활성화로 학습해 이를 훨씬 큰 수의, 드물게 활성화되고 개별 의미를 갖는 특징으로 분해하는 해석 가능성 도구다. **기계적 해석 가능성**의 실무 도구다. 학습 후 특징은 분석뿐 아니라 개발 도구로도 쓰인다. 프롬프트 엔지니어링 없이 내부 특징을 조작하는 추론 시 조향, 벤치마크 중복과 역량 범위를 대리 측정하는 평가 분석, 데이터 분류와 정리, 지도 미세 조정과 RL을 위한 사후 학습 지원이 가능하다. Alibaba의 **Qwen-Scope** (arXiv 2605.11887, May 12, 2026 제출)는 최첨단 공개 가중치 계열을 위해 만든 공개 사례다. Qwen3와 Qwen3.5의 일곱 변형에 걸친 14개 SAE 그룹이며, 밀집형과 MoE를 포함해 1.7B부터 35B 매개변수까지 아우른다(Qwen3-1.7B부터 Qwen3.5-35B-A3B). 9장 참조.

**상태 대체**
긴 상호작용 도중 **에이전트 메모리**에 저장된 사실, 제약, 결정이 수정되어 저장값이 더 이상 유효하지 않은 경우다. 이 분야가 표준으로 삼은 회상 중심 벤치마크에는 구조적으로 드러나지 않는 실패에 이름을 붙인다. 사용자가 *과거에* 지지했던 값을 자신 있게 반환하는 저장소도 적중으로 채점되기 때문이다. **StateMemBench** (arXiv 2608.19652, August 20, 2026)는 접근 통제, 아첨 성향에 이은 세 번째 메모리 통제 평가 축으로 이를 제시했다. 다중 세션 시나리오 234개와 폐쇄 후보군 채점으로 상태 추적 실패를 일반 검색 오류에서 분리한다. 같은 논문의 StateMem 기법은 대체 관계와 관계적 의존성을 검색에 맡기지 않고 명시적으로 추적한다. 6장 참조.

**System Prompt (시스템 프롬프트)**
당신의 대화가 시작되기 전에 AI 모델에 주어지는 숨겨진 지시문으로, 모델의 역할, 규칙, 행동을 설정합니다. 직원이 첫 출근 전에 읽는 직무 기술서와 같습니다.

### T

**Task Budget (태스크 버짓)**
Anthropic이 Claude Opus 4.7에서 도입한 하네스 기본 기능이다(April 2026, 베타 헤더 `anthropic-beta: task-budgets-2026-03-13`). 호출자가 사고, 도구 호출, 도구 결과, 최종 출력을 포함한 전체 에이전트 루프의 권고 토큰 예산을 선언하면, 모델은 작업 중 줄어드는 잔여량을 받아 각 단계에 검색, 추론, 종합을 얼마나 더 투입할지 판단한다. 모델에게 보이지 않는 강제 상한인 `max_tokens`와는 다르다. 예산은 강제되지 않는 권고이며, 빠듯한 예산에서 비정상적으로 거절하는 동작을 막기 위해 최소 20K 토큰이다. 작업 예산은 "how hard to think about each step"을 수동 조정 매개변수가 아닌 관리형 계약으로 노출하는 최초의 공급업체 출시 기본 기능이다.

**시간적 정책**
AWS가 Amazon Bedrock AgentCore에 August 6, 2026 출시한 게이트웨이 적용 인가 기본 기능이다. 일반 정책이 "may this agent make this call,"을 묻는 반면, 시간적 정책은 같은 세션에서 에이전트가 *이전에* 취한 행동을 기준으로 호출을 평가한다. 결정론적이고 기본 거부하며, 모든 기록을 남기고 에이전트 코드 밖에서 적용되므로 어떤 프롬프트나 모델의 판단도 이를 말로 우회할 수 없다. 정책은 AI 에이전트를 위해 만든 새로운 Apache-2.0 오픈소스 정책 언어 **Dogwood**로 작성한다. 명시된 용도는 지시문으로 막을 수 없는 실패 양상이다. 데이터 조작 방지(에이전트가 전달하는 값이 앞선 호출의 실제 반환값과 일치해야 함), 누적 세션 비용 상한, 권한 있는 작업 전에 사람의 승인을 요구하는 작업 순서가 해당한다. 단일 작업의 강제 상한(AgentCore Payments, May 2026)을 한 호출에서 세션 이력으로 일반화한다. 하네스 설계의 권한 축에 상태 유지형 집행 계층이 더해지는 것이다.

**Titans**
메모리가 외부 벡터 저장소나 고정된 어텐션 창 대신, 추론 시 경사 하강법으로 스스로 갱신하는 학습 가능한 신경 모듈인 Google Research의 April 2026 아키텍처 계열이다. 비슷한 매개변수 수에서 Titans가 장기 회상과 다중 홉 추론 벤치마크에서 Mamba-2, Gated DeltaNet, Transformer++를 능가한다고 보고됐다. "context"와 "fine-tuning."의 경계를 흐린다.

**Token (토큰)**
AI 모델이 읽고 쓰는 기본 단위로, 영어에서는 대략 단어의 사분의 삼에 해당한다. 모델은 토큰 단위로 사고하며 가격과 컨텍스트 한계도 토큰으로 측정한다.

**Tool Use / Function Calling (도구 사용 / 함수 호출)**
AI 모델이 텍스트 생성뿐 아니라 외부 행동 — 웹 검색, 코드 실행, API 호출 — 을 트리거할 수 있는 능력.

### V

**Vector Database (벡터 데이터베이스)**
임베딩을 저장하고 검색하기 위해 전용으로 설계된 데이터베이스. 수백만 항목 중에서 가장 유사한 항목을 빠르게 찾을 수 있게 합니다. 대부분의 RAG 시스템의 엔진입니다.

### W

**Wikilink**
Obsidian 같은 도구에서 사용되는 이중 대괄호 링크(예: `[[Note Title]]`). 한 노트를 다른 노트에 연결하여 연결된 지식의 웹을 만듭니다.

### X

**x402**
기계 사이의 인밴드 스테이블코인 결제를 위해 HTTP 상태 코드 402 ("Payment Required")를 되살린 공개 프로토콜로, 에이전트와 자원 간 거래에 쓰인다. Coinbase가 시작했으며, 최초의 대형 클라우드 사업자 관리형 구현은 AWS AgentCore Payments(May 7, 2026)다. 도구 계층의 MCP에 대응하는 "value-layer"다. MCP가 에이전트의 API 접근 방식을 표준화한다면, x402는 API에 대금을 지불하는 방식을 표준화한다. AWS 공식 지원 이전에도 late April 2026까지 활성 에이전트 69,000개와 누적 거래액 약 $50M의 실적이 있었다.
