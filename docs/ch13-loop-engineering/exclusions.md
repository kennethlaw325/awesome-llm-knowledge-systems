# Exclusions and corrections — Loop Engineering wave

The "loop engineering" discourse spread quickly and picked up several claims that did not survive primary-source verification. Each was dropped or corrected before drafting. They are listed here neutrally, with the reason and (where relevant) the value actually used in the chapter, so the exclusions are on the record without re-circulating the unverified specifics.

## Dropped (no primary source; not in the guide)

- **A viral "prompt engineering to loop engineering" post attributed to a prominent AI researcher.** The cited post ID does not resolve and no matching post exists in that account's timeline for the claimed date. Dropped entirely.
- **A reception-percentage split** (a "genuine shift" vs "premature" ratio) presented as if measured. It traces to one unsourced blog narrative with no methodology or poll behind it, and view-count figures conflict across aggregators. Dropped; the split is described only qualitatively.
- **A fixed launch-day view figure** for the catalyst post. Only the live impression count was verifiable, so the chapter quotes that as a mid-July figure instead.
- **Unverifiable productivity statistics attributed to the head of Claude Code** (a merged-code percentage and an output-boost multiplier). The cited posts return 404 and no primary source was located. Dropped; only his qualitative "I write loops" framing is used, flagged as a spoken quote.
- **A multi-rung autonomy scale attributed to the head of Claude Code.** No fetched source attributes any such scale to him; his own framing is a three-stage progression. Graduated autonomy is referenced, if at all, only as generic common practice, with no attributed levels.
- **A vendor "loop engineering" training-course claim.** The named course catalog contains no such course. Dropped as refuted.
- **A named ticketing tool and a "finds docs" step** in Stripe's deterministic pre-run assembly. Neither appears in Stripe's blog or the podcast; the blog's pre-run language is limited to running MCP tools over likely-looking links. Softened to that.
- **Low-level page-structure inspection** in the evaluator description. The source describes clicking, screenshotting, and testing UI features, API endpoints, and database states; a specific low-level inspection term used elsewhere is absent from it. Replaced with the source's own language.
- **An overstated characterization of the hill-climbing rung** (as modifying its own harness rather than improving over runs). The source frames it as self-improvement; the stronger phrasing is not in the text. Used the self-improvement framing.
- **Fabricated per-model benchmark numbers** on Snorkel's Continual Learning Bench (a multi-stage memory scale with per-model percentages). None appear in the paper or Snorkel's primary pages; only the qualitative Fable-backbone finding and the aggregate launch figure are used.

## Corrected (right value used)

- **`/loop` version.** An incorrect patch version circulated; the chapter uses the version from the official changelog, v2.1.71.
- **Codex custom-cadence mechanism.** Characterized elsewhere with the wrong mechanism name; the official docs specify an RFC 5545 recurrence rule (RRULE), which is what the chapter states. The feature is titled "Scheduled tasks," not a named sidebar tab.
- **Osmani's building blocks.** Framed elsewhere as six co-equal items; his heading is "The five pieces, and then notes" — five pieces plus external state. Used as five-plus-state.
- **Steinberger quote + attribution.** Quoted with the full opening clause and original punctuation; he did not coin "loop engineering" (his post uses no such phrase), so the naming is attributed to Osmani's essay and the tech press.
- **Cherny quote.** No single canonical verbatim exists (spoken, transcribed inconsistently across outlets, some citing a different podcast); the most-cited transcription is used and the inconsistency is flagged in-text.
- **Rajasekaran date.** The post is dated March 24, 2026, which the chapter uses; it predates the June naming week, and the chapter notes the practice ran ahead of the label. The "shared context" causal explanation, absent from the post, is not stated.
- **LangChain rung headings + "loopcraft."** The page's own mixed "Loop 1" / "Level 2/3/4" heading scheme is reproduced as written; "loopcraft" is attributed to Swyx (the page's own attribution), not to LangChain.
- **鱼皮 reach + originality.** Only the verifiable GitHub follower figure is used as a reach proxy; larger total-following numbers are omitted. His four-stage nesting and horse metaphor are attributed to him as synthesis, not as originating the underlying terms.
- **Stripe date + sourcing.** Dated March 2026 (month precision; episode day disputed across sources); the devbox / EC2 and "cattle not pets" details are attributed to Stripe's dev blog, not the podcast.
- **@ClaudeDevs label nuance.** The X article is titled "Getting started with loops" and teaches "loops"; the "loop engineering" label is the canonical Claude blog mirror's framing, not the vendor's product vocabulary. Stated that way.
