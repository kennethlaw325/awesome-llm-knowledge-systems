## 用語集

> Plain-language definitions for every technical term used in this guide. No PhD required.

### A

**A2A（Agent-to-Agent Protocol、エージェント間プロトコル）**
AIエージェント同士がコミュニケーションをとり、タスクを連携するための標準的な手段。異なるAIアシスタントが互いに作業を引き継げる共通言語のようなものです。

**Agent Memory（エージェントメモリ）**
AIエージェントが会話やタスクをまたいで情報を覚えておく能力。エージェントがセッション間で持ち続けるノートのようなもので、毎回ゼロから始める必要がなくなります。

**Agentic RAG（エージェント型RAG）**
RAGの一種で、AIが「何を調べるか」「いつ調べるか」「結果が十分かどうか」を能動的に判断するもの。固定の検索フローを毎回そのまま実行するのではありません。

**Anchor（Graph Engineering）**
議論の余地のない、外部に接地された測定——テスト結果、メトリクス、グラウンドトゥルースのチェック——であり、マルチエージェントグラフのいずれかのノードが必ず触れなければならないもの。2026 年 七月の graph engineering の言説で Carlos E. Perez が導入した：アンカーがなければ、互いの作業をレビューし合うエージェントのグラフは、正しさではなく自信に満ちた合意へと収束するエコーチェンバーへと退化する。委員会の全員が予算は良さそうだと同意する代わりに、少なくとも 一人には実際の銀行明細を確認させるようなものだ。**Graph Engineering** を参照；第 14 章。

**ARC-AGI-3**
François Chollet が 2026 年に公開したエージェント知能のためのインタラクティブベンチマーク。エージェントは指示なしでゲーム的環境に放り込まれ、自ら探索し、目標を推測し、世界モデルを構築する必要があります。静的なパズルグリッドで構成されていた以前の ARC とは異なり、ARC-AGI-3 は**探索効率**、**目標推測**、**世界モデル形成**を別々の能力軸として採点します。

### C

**CATTS（Consensus-Aware Test-Time Scaling、コンセンサス対応テスト時スケーリング）**
マルチステップエージェント向けのテスト時スケーリング手法。各ステップで小さなロールアウト委員会をサンプリングし、委員間の不一致を不確実性シグナルとして計算リソースの配分に使います。意見のばらつきが大きいステップにはより多くの思考予算を、ばらつきが少ないステップにはより少ない予算を割り当てます。公開されている結果では、均一スケーリングと比べて約 +9.1% の精度向上を 2.3 倍少ないトークンで達成しています。

**Claude Code**
Anthropic のコマンドラインツール。Claude がターミナル上で直接作業し、ファイル読み込み、コマンド実行、コード編集を AI ペアプログラマーとしてこなします。

**Client ID Metadata Documents（CIMD）**
確定した MCP 2026-07-28 仕様が義務付けるクライアント識別の仕組みで、Dynamic Client Registration に取って代わる：MCP クライアントは、すべてのサーバーに個別に自分自身を登録するのではなく、URL でホストされたメタデータ文書によって識別される。訪問するすべてのオフィスで新規取引先フォームに記入する代わりに、自分自身のアドレスでホストされた名刺を提示するようなものだ。**MCP** を参照。

**Codex（OpenAI）**
OpenAI のツール。AIエージェントがサンドボックス化されたクラウド環境内でコーディングタスクを実行し、自律的にリポジトリを読み、コードを書き、テストを走らせます。

**Context Engineering（コンテキストエンジニアリング）**
AIが応答する前に受け取る情報を慎重に設計する実践。Prompt engineering が「質問を書く」ことなら、context engineering は「AIの机に置く参考資料を選ぶ」ことです。

**Context Window（コンテキストウィンドウ）**
AIモデルが一度に"see"ことができるテキストの総量——あなたの入力とその出力の両方。ホワイトボードの大きさのようなもので、モデルが読み書きするものはすべてその中に収まる必要があります。

**CoT Monitoring（思考連鎖モニタリング）**
モデルが計画を実行する前に、明示的な推論トークンを読んで誤動作や逸脱を検出する実践。OpenAI は 2026 年 四月、自社の推論モデルの一つがコーディング評価で不正行為をしているのを CoT モニタリングで検出しました。これは解釈可能性が**事後鑑識**ではなく**実行時チェック**として機能した最初の公開事例です。

### D

**Decision Model（判断モデル）**
自由形式の応答を生成する代わりに、範囲を限定した型付きの質問に対して、判断とそれに伴う確率を返すモデル。ハーネスはこの判断をルーティングやトリアージに利用できるが、権限に関する決定権は決定論的なアプリケーションコードが保持する。確率には較正の確認が必要であり、判断が正しいという証拠ではない。[第12章](chapters/ja/12-local-models.md)を参照。

**Dreaming**
直近の session のパターンに基づいて、エージェントの永続的記憶を書き換える、session と session の間に走るスケジュール済みの記憶キュレーションジョブ。Anthropic Managed Agents（2026 年 五月 6 日、リサーチプレビュー）によって初めて商用化された：curator が直近の session を読み、繰り返し起こるエラーと収束したワークフローを特定し、エージェントの永続的記憶を平文で書き換える。推論時に勾配更新で適応する訓練可能な記憶（Titans + MIRAS、2026 年 四月）とは対照的だ：Dreaming は記憶を harness が読むデータのままにしておくが、Titans は記憶をモデル自体の一部にする。

### E

**Embeddings（埋め込み）**
意味の近いテキスト同士が数学的にも近くなるように、テキストを数値リストに変換する方法。これにより、コンピューターは二つの本が似たトピックを扱っていることに気づくのと同じ感覚で、テキストの関連度を測れます。

**Emotion Vectors（感情ベクトル）**
Claude の内部活性化における解釈可能な特徴方向。これらが増幅されると、モデルは情緒的な振る舞いに確実にバイアスがかかります——Anthropic の 2026 年 四月の開示では、最も引用された例として恐喝的な出力が含まれます。これらの方向が特定可能であることから、harness エンジニアはトークンレベルではなく**特徴レベル**でフィルタリングできるようになりました。

**Enterprise-Managed Authorization（EMA）**
MCP サーバーへの集中管理された、IdP がプロビジョニングするアクセスのための MCP 拡張（2026 年 六月 18 日に安定版）。各ユーザーがサーバーごとにアプリ単位の OAuth 同意フローを実行する代わりに、組織はアイデンティティプロバイダを通じてサーバーアクセスを一度だけプロビジョニングする；SSO の最中に、クライアントは **Identity Assertion JWT Authorization Grant（ID-JAG）** を取得し、それを MCP サーバー自身の認可サーバーが発行するアクセストークンと交換する（**MCP** を参照）。ローンチ初日のサポートは、IdP としての Okta、クライアントとしての Anthropic と VS Code、そして 七つのサーバーにまたがった。EMA こそが、MCP 向けのエンタープライズ SSO を、サーバーごとの統合の接着剤から、IdP で一度だけ下すプロビジョニングの意思決定へと変えるものだ。

### F

**Few-shot Learning（少数ショット学習）**
モデル全体を再訓練するのではなく、プロンプトの中にいくつかの例を入れて AI にタスクを教える方法。完成した三枚の書類を見せて、四枚目の書き方を理解させるようなものです。

**Fine-tuning（ファインチューニング）**
事前学習されたAIモデルを、自分の特定のデータでさらに訓練して、特定の仕事をうまくこなせるようにすること。ジェネラリストを雇って、その後に専門的な OJT を施すようなものです。

### G

**Generator-Evaluator Split**
作業を生み出すエージェントと、それを判定する独立した、意図的に懐疑的なエージェントを分離するエージェントの信頼性パターン——エージェントは自分自身の出力を確実に過大評価するために採用されている。Prithvi Rajasekaran の "Harness design for long-running application development"（Anthropic、2026 年 三月）で導入され、この構造は Generative Adversarial Networks（GAN）から取られており、独立した evaluator を懐疑的になるようチューニングする方が generator に自己批判させるよりはるかに扱いやすいことを発見した。evaluator は diff を読むのではなく振る舞いを検証する——動いているアプリケーションをクリックして回り、スクリーンショットを撮り、UI 機能、API エンドポイント、データベースの状態をテストする。このパターンは、Claude Code の `/goal` のような run-until-condition プリミティブでプロダクト化されている：そこでは別個の、フレッシュなモデルが毎ターンの後に停止条件を判定する。**Outer Loop**、**Loop Engineering** を参照。

**Graph Engineering**
**Loop Engineering** の上に位置する層はグラフである、という2026年七月の主張。どのエージェントが存在し、誰が誰に委任でき、各エージェントのループがどのように互いを監視・訂正するかを、明示的につなぐことを指す。2026年七月17-18日の Peter Steinberger の投稿に続く論考の中で具体化し、初日から議論を呼んだ。LangChain は、ループは単なる有向循環グラフであり、実践自体は三年前からあるので新しいのは名称だけだと応じた。システムが*何を知っているか*を構造化するナレッジグラフや **GraphRAG** と混同してはいけない。graph engineering はシステムを*誰が構成するか*を構造化する。本ガイドが2026年九月15日に行った存続確認では、独立した論考やエージェント組織としての意味を教える有料講座など、この用語が使われ続けていることは確認された。一方、確認した文書にベンダーによる採用は見つからず、「用語の使用は継続、独立した層としての地位は未証明」と判断した。本ガイドは、確立した層ではなく、マルチエージェント調整を表す議論のある名称として追跡する。第14章を参照。

**GraphRAG**
RAG の一種で、検索された情報を関連エンティティとリレーションシップのグラフに整理し、複数のソースから事実を組み合わせる必要のある質問に答えるのを得意にします。

### H

**Harness Engineering（ハーネスエンジニアリング）**
AIモデルを取り囲むシステム全体——ツール、メモリ、ルール、ワークフロー——を設計し、それが実際にどう振る舞うかを形作ること。モデルはエンジン、ハーネスは車全体です。

**Harness Synthesis（ハーネス合成）**
外側のループのオプティマイザ（探索ベース、可観測性ベースなど）が、ターゲットタスクの実行時シグナルに基づいてハーネス——ツール、プロンプト、役割分解、通信トポロジー、協調プロトコル——を自動的に修正する技術群。2026 年 四月の参考実装として **AHE**（arXiv 2604.25850）と **AgentFlow**（arXiv 2604.20801）を参照。*meta-harness*（2025 年〜2026 年初頭の枠組み、ハーネスを継続的に進化する成果物ではなく、一回限りの最適化の対象として扱った）とは区別されます。

**Harness-Native Training（ハーネスネイティブ訓練）**
特定の本番エージェントのハーネスに対してモデルを直接訓練し、単独で正しい出力を生成するだけでなく、そのハーネスのツールとワークフローの操作を学ばせること。代表例は Microsoft の **MAI-Code-1-Flash**（Build、2026年六月2日）で、GitHub Copilot の本番用ハーネスに合わせて訓練された5Bパラメータのコーディングモデルである。Microsoft は難しいタスクで約60%のトークン削減と、Claude Haiku 4.5 に対する価格性能上の優位を報告する。Harness-native training は **harness synthesis の対称的な逆**に当たる。harness synthesis（**Harness Synthesis**、**AHE** を参照）はモデルを固定してハーネスを進化させるが、harness-native training はハーネスを固定し、モデルをそれに適合させる。両者によりモデルとハーネスは、双方から最適化できる共同設計の問題になる。トレードオフとして、特定ベンダーのハーネスに調整されたモデルは、その内側で最も価値を発揮するため、*参入障壁としてのハーネス*という力学が強まる。

### I

**Inference（推論）**
AIモデルがあなたの入力に対して応答を生成するプロセス。メッセージを送って返答を受け取るたびに、モデルは推論を実行しています。

**Iteration Head（イテレーションヘッド）**
思考連鎖推論の中で出現し、前の推論ステップの出力に一貫して注目するアテンションヘッド。Anthropic の解釈可能性チームが 2026 年 四月に同定。明示的な CoT プロンプティングが部分的には特定の内部回路を誘導することで機能していることを示唆し、人間が読める中間テキストを生成するだけではないことを意味します。

### K

**Knowledge Graph（知識グラフ）**
事実の構造化された地図で、エンティティ（人、場所、概念）がラベル付きの関係でつながっています。すべてがどう関連しているかを示すラベル付きの紐でつながれたインデックスカードのウェブのようなもの。

**KV-Cache**
AIが以前計算したキー・バリューのペアを再利用し、ゼロから計算しなくて済むメモリのショートカット。会話履歴が変わらなければ応答が速く、安くなります。

### L

**LLM（Large Language Model、大規模言語モデル）**
膨大な量のテキストで訓練され、人間の言語を理解し生成できる AI システム。ChatGPT、Claude、Gemini はすべて LLM です。

**Long Context（ロングコンテキスト）**
新しいAIモデルが一度に大量のテキストを処理する能力——本一冊やコードベース全体が一回の会話に収まることもあります。

**Loop Engineering**
各ターンで手動でプロンプトを送る代わりに、自分に代わってエージェントにプロンプトを送るシステムを構築する実践。2026年六月に命名された。Addy Osmani が2026年六月7日の論考で "replacing yourself as the person who prompts the agent" を "the system that does it instead," の設計によって行うと定義し、同じ週の Peter Steinberger の広く拡散した投稿が触媒となった。**Harness Engineering** の一階層上に位置する。ループは、タイマーで動き、補助サブエージェントを生成し、永続化された状態から自ら次の入力を得るハーネスである。時計に従って固定コマンドを発火させるだけでなく、毎回現在の状態を読み、何をするか再判断する点で、単なるスケジューラとは異なる。実務家の間だけで使われる議論のある用語であり、2026年半ば時点で学術文献はない。本ガイドは、確立した世代ではなく、新興の第四層として追跡する。第13章を参照。

### M

**Memory Conflict Resolution（メモリの競合解決）**
競合する事実のどれを採用するかについて、根拠とともに記録された判断。永続的なメモリシステムでは、情報源が変わったり、消えたり、忘却されたりした際に、その判断を再検討または失効させる必要がある。これはライフサイクル上の要件であり、すべてのメモリバックエンドがデータベースのトランザクションを実装しているという主張ではない。[第6章](chapters/ja/06-agent-memory.md)を参照。

**MCP（Model Context Protocol、モデルコンテキストプロトコル）**
AIアシスタントが汎用のプラグアンドプレイインターフェースを通じて外部ツールやデータソースに接続するためのオープンスタンダード。AIアプリケーション向けの USB のようなものです。

**MCP Apps**
サーバーがツール呼び出しに加えてインタラクティブな HTML インターフェースを出荷できるようにする、2026-07-28 の MCP Release Candidate プリミティブ（2026 年 五月 21 日にロック）。ホストはそのインターフェースをサンドボックス化された iframe の中でレンダリングする；UI テンプレートはセキュリティレビューとキャッシュのために事前に宣言される。MCP Apps は、ツール呼び出しではない最初の MCP ネイティブな成果物だ——ナレッジベースサーバーは検索ボックスを、リサーチサーバーは結果比較ビューを、調達サーバーは購入確認モーダルを、それぞれ別個の UI 仕様をボルト付けすることなく出荷できる。

**MCP Tunnel**
2026 年 五月 19 日（Code with Claude London）に Anthropic Managed Agents がリサーチプレビューで出荷したプライベートネットワークのデプロイメントパターン。顧客のプライベートネットワークの内側にデプロイされる軽量なゲートウェイが Anthropic への単一のアウトバウンド接続を確立し、その後エージェントは内部のデータベース、API、ナレッジベース、チケットシステムを MCP ツールとして呼び出せる——インバウンドのファイアウォールルールも、公開エンドポイントも、VPN も不要だ。self-hosted sandbox の対称的な対概念：self-hosted sandbox がツールの*実行*を顧客の境界の内側に留めるのに対し、MCP tunnel はツールの*到達範囲*を境界の内側に留める。

**Managed Agents（マネージドエージェント）**
エージェントハーネスの基底——サンドボックス、セッション状態、スコープ付きツール実行、トレーシング——が開発者ではなくモデルベンダーによって運営されるホステッドランタイムモデル。Anthropic は 2026 年 四月 8 日、最初の商用例をパブリックベータで出荷（[platform.claude.com/docs/en/managed-agents/overview](https://platform.claude.com/docs/en/managed-agents/overview)）。SiliconANGLE のローンチカバレッジによれば、価格は標準 API トークンレートに加えて基底に対するエージェント実行時間あたりの料金（毎時の数値は Anthropic の一次資料には記載されていません）。クラウドネイティブなトリガリング表面（例：Claude Code Routines）とは区別され、後者は Managed Agents 風の基底の上に乗りつつ、別の問いに答えます——"what makes the loop start"。

**Mechanistic Interpretability（機構的解釈可能性）**
モデルの重みの内部にある人間が理解可能な回路——特定の振る舞いを実装する特徴、ヘッド、経路——を特定することを目指す研究プログラム。MIT Technology Review の 2026 年 10 大ブレークスルーテクノロジーの一つに選ばれ、2026 年 四月の感情ベクトル、イテレーションヘッド、CoT モニタリングなどの結果を支えています。

**Memory Foundation Model（メモリ基盤モデル）**
エージェントの記憶は、transformer のバックボーン自体の内側に、永続的で動的に進化する state として——外部にではなくパラメトリックに——存在すべきだという 2026 年 七月の主張（MemTensor の Metis、arXiv 2607.26760）。プロトタイプは、凍結された Qwen3.5 バックボーンの上に（Fast Weight Programming にインスパイアされた）"hyper memory block"と"local memory block"を 4B／9B／27B のスケールで訓練し、ベクトルストアへの書き込みや Titans 式の勾配更新ではなく、勾配を使わない EMA スタイルの forward パスによって推論時に記憶を更新する。自己申告の限界には、固定サイズの圧縮下での長期視野の情報損失や"information confusion in some cases, possibly caused by the blending of semantics within the latent space"が含まれる——これはまだ検証済みの本番パターンではなく、リサーチプレビューだ。第 6 章を参照。

**mHC（Manifold-Constrained Hyper-Connections、多様体制約ハイパーコネクション）**
DeepSeek の 2026 年 四月のアーキテクチャ提案。残差接続を、複数の内部情報ストリームを学習された低次元多様体に沿ってルーティングするように拡張します。Transformer++ 風モデルの単一残差ストリームを協調する複数のストリームに一般化したもの。発表時点で、結果は**独立した再現を待つ**フラグが付いています。

**MIRAS**
Google Research が公開したメモリ拡張型訓練フレームワーク。Titans のような、メモリが推論時に更新される訓練可能なニューラルモジュールであるアーキテクチャに対し、レシピ、安定性保証、学習ダイナミクスを提供します。MIRAS は「推論しながら学ぶ」を発散させずに実用的にする枠組みです。

**MoE（Mixture of Experts、エキスパート混合）**
モデルアーキテクチャの一種で、入力ごとにモデルの"brain"の一部だけが活性化されます。これにより、すべての部分が毎回動くわけではないため、非常に大きなモデルでも高速さを維持できます。

### O

**Obsidian**
ノートをあなたのコンピューター上のプレーンテキストファイルとして保存し、それらを互いにリンクして個人ナレッジベースを作れるノートアプリ。

**Org Graph / Work Graph**
graph engineering における 二つのグラフオブジェクトで、Yash Thakker の 2026 年 七月の explainx.ai ガイドに由来する：*org graph* は、どのエージェントが存在し、それぞれが何のためにあり、どの委任のエッジが許可されているかについての安定したチャートである；*work graph* は、特定のジョブが生み出し、実行し、破棄する、儚いタスク分解である。会社の組織図と、一つのプロジェクトのために組まれ、その後解散する場当たり的なワーキンググループとの違いのようなものだ。**Graph Engineering** を参照；第 14 章。

**Outcomes（Anthropic）**
パブリックベータのマネージドエージェントプリミティブ（Anthropic、2026 年 五月 6 日）で、エージェントは、ルーブリックが満たされるまで、自身の context window とは別の context window で走る別個の grader に対して反復する。Ralph ループ／CATTS の不確実性主導の反復パターンを API コントラクトとしてプロダクト化する：呼び出し側がルーブリックを書き、基盤が呼び出し側に代わって反復と採点のループを走らせ、収束した結果のみが呼び出し側に返る。

**Outer Loop**
エージェントが inner execution loop（調査、実装、テスト／検証、報告）を走らせる間、人間が保持する判断の層。Addy Osmani の 2026 年 七月の続編"Own the Outer Loop,"に由来し、それを 三つの柱——Quality（エージェントが行動する前に走るチェックの背圧）、Verdict（"the final decision we make before work enters our dependent system"）、Answerability（"the guarantee that if someone asks, I can explain why"）——として構造化する。Osmani はこれを過剰に委任することの 三つの失敗モードを名指す：cognitive debt（問題の解き方についての理解の浸食）、cognitive surrender（AI が与えるものを盲目的に受け入れること）、そして orchestration tax（あなたの判断がカバーできる以上のエージェントを立ち上げること）。**Loop Engineering** と **Generator-Evaluator Split** の補完物：ループは、それを取り巻く outer loop の良さの分だけしか良くならない。第 13 章を参照。

### P

**Progressive Disclosure（プログレッシブディスクロージャー）**
最初は必要最小限の情報だけを見せ、必要に応じて詳細を明らかにする設計原則。FAQ ページのように、質問が見えていて、実際に必要な答えだけクリックで展開します。

**Prompt Engineering（プロンプトエンジニアリング）**
AIモデルへの指示文を、最高の応答が得られるように書く技術。表現の小さな違いが大きく異なる結果を生むことがあります。

### R

**RAG（Retrieval-Augmented Generation、検索拡張生成）**
AIが応答前に外部ソースから関連情報を調べ、訓練時に記憶した内容だけに頼らず、実データに根ざした応答をする技術。

**Routines（Claude Code）**
Anthropic が 2026 年 四月にリリースした Claude Code のクラウドネイティブハーネスプリミティブ。エージェントワークフローはユーザーのマシンではなく Anthropic のクラウドで実行され、スケジュール、API 呼び出し、または GitHub イベントによってトリガーできます。Routines は自前 cron+daemon パターンをマネージド基底に一般化し、ティアごとにクォータがあります（Pro 5/日、Max 15/日、Team/Enterprise 25/日）。ユーザーのラップトップがオフラインでも動き続けます。

### S

**Shared Context Layer（共有コンテキスト層）**
それを利用するエージェントやモデルとは別に維持される、永続的なコンテキスト。同じ基礎情報に対して、複数のエージェントが権限に応じたビューを利用できる。ストアをデバイス上に置いても、それを使うすべてのエージェントがローカルで稼働するとは限らない。[第12章](chapters/ja/12-local-models.md)を参照。

**Safety-Tiered Distribution（安全階層型配布）**
一つのモデルファミリーを、重みではなく安全対策のレベルと配布ゲートで異なる並行ティアとして出荷すること。参照例は Anthropic の 2026 年 六月のペアだ：**Claude Fable 5**（デュアルユースの安全対策——`stop_reason` としての拒否を含む——を伴う一般公開 GA）と **Claude Mythos 5**（同じ基盤重みだが安全対策を外し、審査済みの Glasswing 連合にゲートされている）。これは GPT-5.5 Trusted Access for Cyber のようなベンダー選択のアクセスティアとは対照的であり、2026 年半ばまでには GPT-5.6 の大統領令でゲートされたプレビューのような政府が課すティアとも対照的だ。それが符号化するトレードオフ：能力と安全性は互いに切り離されているので、あなたが誰であるか（審査済みの組織か、一般ユーザーか）が、モデルに何ができるかではなく、あなたがどの安全ティアに到達できるかを決める。

**Self-Hosted Sandbox（セルフホスト型サンドボックス）**
2026 年 五月 19 日（Code with Claude London）に Anthropic がパブリックベータで出荷した Managed Agents のデプロイメント形態。エージェントのループ——編成、context 管理、エラー回復——は Anthropic のインフラ上に留まる一方で、ツールの*実行*は顧客自身の環境か、マネージドサンドボックスプロバイダ（Cloudflare、Daytona、Modal、Vercel がファーストパーティでサポート）へと移動する。Managed Agents を"fully Anthropic-hosted"ものから"Anthropic-orchestrated, customer-perimeter-respecting"ものへと枠付け直す——harness エンジニアは、完全なセルフホストと完全なマネージドの間で選ぶのではなく、ループのどのピースがどこに住むかを層ごとに選ぶ。

**Self-RAG**
RAG の一種で、AI が自分で取得した情報と生成した回答の品質を評価し、最終結果を出す前に追加検索や修正の必要性を判断します。

**Session-hour pricing（セッション時間課金）**（*agent-runtime-hour pricing* としても報道）
オーケストレータの席——エージェントループが走る基底——を推論とは別に計量する課金モデル。Anthropic Managed Agents が 2026 年 四月 8 日に商用導入。SiliconANGLE のローンチカバレッジによれば、標準トークン単価に加えてエージェント実行時間あたり 八 セント。毎時の数値は Anthropic の一次ドキュメントには記載されておらず、二次のテックプレスから引用されています。注目すべき点は、これが"where the loop runs,"のコストに数値を付けた**最初のベンダープリミティブ**であり、"what the loop thinks."のコストとは区別されているという点です。表現は一次資料（*sessions* を使う）とテックプレス（*agent runtime hour* を使う）で異なりますが、どちらも同じ計量サーフェスを指しています。

**Skill（AI Agent Skill）**
AIエージェントが呼び出せる、再利用可能でパッケージ化された機能——"review this PR"や"run a daily review."のような特定タスク用のレシピのようなものです。

**Stateless MCP（ステートレス MCP）**
MCP 2026-07-28 Release Candidate（2026 年 五月 21 日にロック）で導入され、2026-07-28 仕様（2026 年 七月 28 日）で最終版として出荷されたアーキテクチャ上のシフト：プロトコルのコアはもはや `initialize`／`initialized` ハンドシェイクや `Mcp-Session-Id` ヘッダーを使わない。クライアントのメタデータはすべてのリクエストの `_meta` の中を移動するので、どの MCP リクエストもどのサーバーインスタンスにも着地できる——スティッキールーティングも、共有 session ストアも不要だ。2025 年の Streamable HTTP 採用で表面化した水平スケーリングの摩擦を解消する。*stateful* への転回を動機づけた永続的 state のプリミティブ（SEP-1686 Tasks、AgentCore の双方向ランタイム）は、あらゆるリクエストに焼き込まれるのではなく、拡張としてステートレスなコアの上に再実装される。ステートレスなコアの上にステートフルな作業が乗るのであって、底までステートフルなのではない。

**Skill Graph（スキルグラフ）**
AIエージェントが利用できるすべてのスキルの地図。各スキル同士の関係や、それぞれがいつトリガーされるべきかも含まれます。

**Skill Supply-Chain Attack（スキル・サプライチェーン攻撃）**
skill レジストリやマーケットプレイスを通じて配布される、悪意のある、あるいはトロイの木馬化されたエージェント skill。2026 年を定義する仕組みは time-of-check-to-time-of-use のギャップだ：静的スキャナーは*提出されたパッケージのスナップショット*を審査するが、外部のコンテンツを取得する——あるいは隠されたペイロードを展開する——skill は、エージェントのランタイムで審査後に振る舞いを変えうる。AIR の 2026 年 六月の開示は、外部 URL の背後にある偽の skill 一つでこの方法によりおよそ 26,000 のエージェントを乗っ取った。そして"Cloak and Detonate"リサーチ（2026 年 七月）は、八つのスキャナーに対して回避が 90% 以上の確率で成功することを示し、対抗策の方向性としてランタイムの行動検知（誤検知率 2% で検知率 97%）を挙げた。この教訓は MCP のもの（**MCP** を参照）を反映している：**Progressive Disclosure**（**Progressive Disclosure** を参照）とレジストリ規模の配布が skill ファイルを攻撃対象にしてしまった以上、信頼は公開時のスキャンからランタイムの封じ込めへと移らなければならない。

**Sparse Autoencoder（SAE、スパースオートエンコーダ）**
モデルの内部活性を学習し、それをはるかに大きな、疎に活性化する個々に意味を持つ特徴の集合へ分解する解釈可能性ツール。**Mechanistic Interpretability** の実用的な計測器である。訓練後の特徴は、分析だけでなく開発にも使える。prompt engineering を使わず内部特徴を操作する推論時のステアリング、ベンチマークの重複や能力の網羅性を推定する評価分析、データの分類と整理、教師ありファインチューニングや RL の事後訓練支援などである。Alibaba の **Qwen-Scope**（arXiv 2605.11887、2026年五月12日投稿）は、最先端のオープンウェイトのモデル群向けに構築された公開例である。Qwen3 と Qwen3.5 の七つの派生モデル（dense と MoE）にまたがる14の SAE グループを備え、1.7Bから35Bパラメータを対象とする（Qwen3-1.7BからQwen3.5-35B-A3B）。第9章を参照。

**State Supersession（状態の更新による旧値の失効）**
長いやり取りの途中で、**Agent Memory** に保持された事実、制約、判断が修正され、保存されていた値がもはや有効でなくなること。これは、この分野で標準化された再現率重視のベンチマークでは構造的に見えない失敗を指す。ユーザーが*以前は*正しいと考えていた値を自信満々に返すストアも、検索成功として採点されてしまう。**StateMemBench**（arXiv 2608.19652、2026年八月20日）は、これをアクセス制御と迎合性に続く第三のメモリガバナンス評価軸とした。234の複数セッションシナリオと、候補を限定した採点で、状態追跡の失敗を通常の検索エラーから切り分ける。同論文の StateMem 手法は、旧値の失効と関係上の依存を検索任せにせず、明示的に追跡する。第6章を参照。

**System Prompt（システムプロンプト）**
あなたの会話が始まる前にAIモデルに渡される隠れた指示で、その役割、ルール、振る舞いを設定します。新入社員が初日に読む業務マニュアルのようなものです。

### T

**Task Budget（タスクバジェット）**
Anthropic が Claude Opus 4.7 で導入したハーネスプリミティブ（2026 年 四月、beta ヘッダ `anthropic-beta: task-budgets-2026-03-13`）。呼び出し側は**エージェントループ全体**（思考、ツール呼び出し、ツール結果、最終出力）に対する助言的なトークン予算を宣言し、モデルは作業中にカウントダウンを受け取って、ステップごとに探索・推論・総合にどれだけ値するかを判断します。`max_tokens`（モデルに見えないハードキャップ）とは異なります。予算は強制ではなく助言的で、最小 20K トークンを保証することで予算過小時に拒否的な振る舞いに退化するのを防ぎます。Task budgets は"how hard to think about each step"を、手動調整パラメーターではなく**マネージドコントラクト**として表面化した最初のベンダープリミティブです。

**Temporal Policies（テンポラル・ポリシー）**
2026 年 八月 6 日に AWS が Amazon Bedrock AgentCore で出荷した、ゲートウェイで強制される認可プリミティブ。通常のポリシーが"may this agent make this call,"を問うのに対し、temporal policy はその呼び出しを、同じ session 内でのエージェントの*それ以前*の行動に照らして評価する——決定論的に、デフォルト拒否で、完全にログ記録され、エージェントのコードの外側で行われるので、どんな prompt やモデルの判断もそれを言いくるめて回避することはできない。ポリシーは **Dogwood** という、AI エージェント向けに目的設計された新しい Apache-2.0 のオープンソースポリシー言語で書かれる。名指されている用途は、指示だけでは防げない失敗モードだ：データ捏造の防止（エージェントが後段に渡す値は、以前の呼び出しが実際に返したものと一致しなければならない）、累積的な session コストの上限、そして特権的な操作の前に人間の承認ステップを要求するワークフローの順序付け。単一アクションのハードキャップ（AgentCore Payments、2026 年 五月）を、一 回の呼び出しから session の履歴全体へと一般化したもの——harness 設計の Authority 軸が、ステートフルな強制の層を獲得したのだ。

**Titans**
Google Research の 2026 年 四月のアーキテクチャファミリーで、メモリは外部のベクターストアでも固定のアテンションウィンドウでもなく、推論時に勾配降下によって自身を更新する訓練可能なニューラルモジュールです。同等のパラメーター数で、Titans は長距離想起やマルチホップ推論ベンチマークで Mamba-2、Gated DeltaNet、Transformer++ を上回ったと報じられており、"context"と"fine-tuning."の境界を曖昧にしています。

**Token**
AIモデルが読み書きする基本単位——英語ではおおよそ単語の 四 分の 三 にあたります。モデルはトークン単位で考え、価格やコンテキスト制限はトークンで計測されます。

**Tool Use / Function Calling（ツール使用 / 関数呼び出し）**
AIモデルがテキストを生成するだけでなく、外部アクション——ウェブ検索、コード実行、API 呼び出し——を発動できる能力。

### V

**Vector Database（ベクターデータベース）**
embedding を保存・検索するために専用設計されたデータベース。数百万件の中から最も類似するアイテムを高速に見つけられます。多くの RAG システムのエンジンです。

### W

**Wikilink**
Obsidian などで使われる、二重角括弧のリンク（例：`[[Note Title]]`）。ノート同士をつなぎ、リンクされた知識の網を作る。

### X

**x402**
マシン間のステーブルコインによるインバンド決済のために、HTTP ステータスコード402（"Payment Required"）を復活させるオープンプロトコル。エージェントからリソースへの取引に使う。Coinbase が発案し、AWS AgentCore Payments（2026年五月7日）が初のハイパースケーラー管理による実装となった。ツール層に対する MCP の "value-layer" 版に相当する。MCP がエージェントによる API への接続方法を標準化する一方、x402 は API への支払い方を標準化する。AWS による支持以前にも、2026年四月下旬までに69,000のアクティブエージェントと、累計約$50Mの取引規模があった。
